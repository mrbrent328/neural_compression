# Neural Compression — Research Log

## Project North Star

> What is the smallest persistent relational structure capable of explaining multiple observations of the same underlying system?

This is the current compressed research question. It may change as evidence changes.

## How to Read This Log

This file is the living research memory. Git history preserves changes in our understanding. Experiment numbers are not the research trajectory; experiments are observations attached to smaller conceptual questions.

Keep separate:

- **Observations:** what an experiment actually showed.
- **Invariants:** patterns that survive changes in observation, traversal, viewpoint, seed, or implementation.
- **Hypotheses:** explanations currently being tested.
- **Rejected explanations:** explanations weakened or ruled out.
- **Open questions:** unresolved uncertainty.
- **Current model:** smallest coherent structural explanation presently supported.
- **Next decision:** experiment that most efficiently separates competing explanations.

When something is surprising or potentially useful later, record it even before its importance is understood.

## Reconstructed Trajectory

The project is best understood as increasingly constrained questions rather than unrelated architectures.

### 1. Can a tiny representation retain useful information?

The initial instinct was broader than simply compressing a model: can a system retain recognizable information about a much larger underlying system while storing dramatically less explicit information?

A recurring idea was that repeated observations of the same underlying thing should not necessarily require independent complete representations.

### 2. What information survives?

Very small latent representations produced organized behavior and geometry. A two-dimensional latent was particularly interesting because it retained structure associated with a much larger system.

The geometry was evidence to investigate, not automatically the object of the research.

### 3. Is the surviving structure persistent?

Across seeds and configurations, organized latent structure appeared repeatedly, although its exact geometry varied. This established that structured information could survive severe compression; it did not establish that latent geometry itself was semantic meaning.

### 4. Is that structure behaviorally meaningful?

Behavioral probes showed that latent geometry and behavior were not related by one universal mapping. Different seeds could produce different relationships, including apparent inversions. This weakened the simple explanation that latent coordinates directly equal semantic meaning.

### 5. Is the apparent structure an artifact of coordinates or observation?

Rotation, viewpoint, and intervention experiments increasingly asked whether a representation describes the underlying system or merely one coordinate system or observation path.

#### Observation basis versus physical rotation

The newer rotation/angle idea should not be interpreted primarily as literal mechanical rotation. The intended variable is a change in **observation basis or observation state**: the same underlying system can produce different observed manifestations under different observation conditions.

Current hypothesis:

> Changing the observation basis can change observed form without changing the underlying system, and combining observations may expose relational information not explicit in an individual observation.

This remains a hypothesis, not an established neural mechanism.

### 6. What persists across observations?

Traversal changes, viewpoint changes, local representations, shared interaction layers, and information-boundary tests increasingly moved the question from what one latent contains to what structure must persist across multiple observations of the same system.

### 7. Current direction: persistent relational structure

The current hypothesis is that the useful compressed object may not be an isolated representation of each observation. It may instead be a small persistent relational structure from which multiple observations can be explained, reconstructed, or predicted.

The target is **minimum reusable structure**, not merely minimum representation size.

## Historical Archaeology: ROCM-test Recovery

On August twenty-six, twenty twenty-six, the repository received commit `7a29f7f` titled **“ROCM-test folder dump.”** This is the historical layer that was missing from the earlier GitHub snapshot. The prior repository state exposed the later experiment sequence beginning around E18; this dump restores the older working material and should now be treated as primary evidence for reconstructing the original trajectory.

The recovered material confirms that the original project had at least two distinct meanings of “compression.”

### Coding compression

The early work included direct neural byte-stream compression. One recovered implementation is a synchronized online neural range compressor: the encoder and decoder initialize the same model state, predict the next byte from a fixed context, range-code the prediction, then both update the model from the observed/decoded byte. The implementation verifies exact reconstruction with SHA-256.

The important conceptual ingredients are:

`observed stream → context → probability model → predicted symbol cost → encode → shared model update`

That branch forces explicit questions about predictability, bit cost, online adaptation, synchronization, and what information is actually reusable.

### The forgotten synchronization insight

The evolution of this code reveals something more important than the codec itself. The model does not need to be transmitted alongside the compressed data if **both sides can deterministically reconstruct the same evolving model state from the same history**. The compressed stream is therefore not merely carrying symbols; it is carrying information that drives two copies of a shared adaptive state machine along the same trajectory.

This is a strong early precursor to the project's later notion of persistent state. The system effectively turns history into state:

`shared initial state + observations → evolving internal state → next prediction`

and the decoder reproduces that state trajectory because it receives the same observations through decoding.

That should be treated as a foundational architectural idea, not merely an implementation trick. It is an early example of **persistent reusable structure emerging through sequential interaction rather than being re-sent from scratch**.

The later versions are explicitly optimizations of the same algorithm rather than new compression methods. This is historically useful because it separates **research evolution** from **implementation evolution**. The core idea stayed stable while the machinery changed around it.

### Representation / model compression

The other branch attempted to retain useful behavior or structure of a larger system using a much smaller latent or parameter representation. This branch eventually led through functional recovery, relational attention, latent geometry, viewpoint/rotation tests, persistent memory, and finally explicit relational structure.

The historical relationship is therefore better represented as:

`raw-data coding → learned predictability → synchronized adaptive state → representation/latent compression → functional recovery → relational attention → latent geometry → observation invariance → persistent structure → relational structure`

The coding branch should not be discarded as obsolete history. It is a concrete precursor to the current question because both branches ask what information is predictable, reusable, and worth preserving.

### Important archaeology rule

Do not retroactively force the current E37 interpretation onto early experiments. First record what the historical experiment actually tested. Then identify which later question it may have informed. An apparently dead-end result may contain a precursor to an idea rediscovered later under different terminology.

### Archaeology targets

As the ROCM-test dump is reviewed, specifically look for:

- forgotten hypotheses that later reappeared;
- early distinctions between storage/coding cost and representation cost;
- places where decoder/model cost was ignored or explicitly counted;
- online or adaptive learning mechanisms;
- observations about reusable information;
- early information-leak or boundary concerns;
- evidence that multiple observations were being treated as views of one underlying system;
- any “holy shit, come back to this later” result that was never incorporated into the main trajectory.

The goal is not to reproduce every historical file. The goal is to recover durable relationships between experiments, observations, and changed hypotheses.

## Foundational Historical Branch: E14B / test14b.py

**E14B has now been explicitly archived in the repository as `ROCM-test/test14b.py`.** It should be treated as a foundational implementation, not merely an old script. The source converts tensors from a GGUF model into a tiled latent representation using a convolutional encoder, stores latent grids in a binary file, and records tensor-level metadata and byte offsets in a JSON index.

The core pipeline is:

`GGUF tensor → normalize/reshape → 256×256 tiles → convolutional encoder → latent grid → binary storage + index`

Several details matter historically:

- Large tensors are spatialized into 256×256 tiles rather than treated only as flat parameter vectors.
- The encoder reduces each 256×256 tile to a `16 × 32 × 32` latent grid. At the raw float32 tensor level this is a nominal **16× reduction in stored values per encoded tile**, before accounting for the encoder itself, decoder, metadata, and any subsequent quantization/entropy coding.
- Small and one-dimensional tensors bypass the latent path and are stored uncompressed.
- The JSON index preserves original shape, flattened shape, padded shape, tile count, latent shape, byte offset, and byte length.
- The implementation is therefore already thinking in terms of **structured local pieces plus an addressable persistent index**, rather than one monolithic compressed vector.

### E14B — the important thing we missed

The most important historical insight is not the nominal compression ratio. It is the **choice to turn a large model into a collection of spatially addressable local representations**.

That is an early ancestor of the current local-unit/relational view:

`large system → local units → compact representation → persistent index`

The later E36/E37 work makes the same structural move more explicitly: persistent units become reusable objects, and relations are added between them. E14B therefore appears, in retrospect, to be an early engineering precursor to the idea that a large system may be better represented as **many reusable local pieces with explicit structure between them** rather than as one compressed monolith.

There is also an important methodological warning in E14B. The script demonstrates a representation pipeline, not by itself a validated lossless or behavior-preserving compression result. The printed `LATENT` ratio is a raw tensor-value reduction, not a complete end-to-end compression ratio. Encoder/decoder cost and reconstruction quality must be accounted for before calling it genuine compression.

### E14B archaeological status

**Status: foundational precursor; not a validated compression result.**

**Recovered idea worth preserving:** local compact representations plus explicit addressing/indexing.

**Potentially missed branch:** learn or test relations *between* latent tiles, and evaluate functional reconstruction rather than raw weight reconstruction.

**Current relevance:** high. E14B may be the earliest concrete implementation in the recovered archive of the architectural instinct that later became “local representations + shared relational layer.”

## Discover Law Branch — Scientific Law Discovery

The recovered `Discover_Law_2.py` and `Discover_Law_3.py` establish a separate but highly relevant branch of the project. These experiments are **symbolic regression, not neural-network law discovery**.

Discover Law Two creates noisy observations from a hidden generating relationship, gives the discovery engine only the observed variables and outputs, constructs a predefined mathematical feature library, searches combinations of candidate terms, fits coefficients on training observations, evaluates on held-out observations, and finally tests the selected relationship on fresh data before revealing the hidden law.

Discover Law Three extends this direction with explicit complexity-aware scoring. It searches equations with different term counts, evaluates several complexity penalties, compares prediction error against structural complexity, and evaluates the selected model on fresh noiseless data. The hidden law is not provided to the discovery engine.

The key historical progression is:

`observe data → search explanatory structure → validate on unseen data → prefer simpler explanation → reuse the discovered generator`

This branch is important because it demonstrates that the project's objective is separable from neural networks. A neural network is an implementation candidate, not a requirement of the research question.

### Discover Law — conceptual significance

The important question is not merely “can we fit the data?” It is:

> **Can observations reveal a compact reusable structure that generates or explains those observations?**

This creates a third distinction alongside raw storage and predictive modeling:

`raw storage → remember observations`

`predictive model → remember enough structure to predict observations`

`generative structure → discover a compact rule/relationship that can produce or explain observations`

Discover Law Two/Three primarily test the third category in a restricted mathematical hypothesis space. They do **not** establish arbitrary law discovery from an unrestricted space, and they do not establish that a neural network is necessary.

This branch should remain central rather than being treated as a side experiment that was “to revisit later.” It is a historical bridge between compression, prediction, and explanatory structure.

## Representation Similarity versus Reconstructive Sufficiency

A major conceptual refinement emerged during archaeology and discussion of earlier results:

> **A system may achieve exact reconstruction without maintaining a bitwise- or parameterwise-faithful internal representation. What matters may be whether the distributed representation preserves sufficient constraints to uniquely reconstruct the target.**

A discrete output can be reproduced exactly even when its internal representation does not resemble the output's surface form. A human recalling a phone number is an intuitive example: the reproduced sequence can be exact without implying a literal binary copy stored at one location.

This distinction should be applied when revisiting historical Neural Compression results. Some experiments may have produced unexpectedly good prediction or reconstruction despite poor representation-level similarity metrics. Such cases should not automatically be treated as failures. They may indicate that the representation preserved the distinctions or relationships necessary for the behavior without preserving the target's surface form.

Therefore, explicitly search the historical archive for:

`poor parameter/latent similarity + unexpectedly strong functional prediction or reconstruction`

Such cases may be evidence that a metric measured **representation similarity** rather than **information sufficiency**.

This is a research hypothesis, not a claim about a specific biological mechanism.

### Consequence for compression

Compression does not necessarily require preserving the shape of information. A more general framing is:

> **Compression requires preserving enough information to distinguish and reconstruct what matters.**

This suggests future metrics around **reconstructive sufficiency**, **constraint preservation**, or related information-boundary measures rather than relying only on parameterwise or latentwise similarity.

## Constraint-Based and Bidirectional Reconstruction Hypothesis

A further hypothesis emerged from considering interrupted human thought and missing intermediate states.

Instead of only predicting forward:

`A → B → ? → D`

an uncertain state might be reconstructed by satisfying constraints from both directions:

`A → B → ? ← D`

The candidate state is then the state that makes both neighboring relationships plausible. This is a **bidirectional constraint-propagation hypothesis**, not yet an experimental result.

This may be relevant because it changes the problem from predicting a missing value directly toward finding the smallest state that satisfies the relationships imposed by surrounding observations.

## Generalized Data Discovery Hypothesis

The Discover Law experiments raise a broader question: if symbolic regression can discover a compact generator for data with a known mathematical vocabulary, can the same principle be generalized to arbitrary data types?

The proposed direction is not to assume a neural network. Instead, construct a sufficiently general hypothesis space of transformations and relationships and search for the smallest reusable structure that predicts or reconstructs held-out observations.

For time-series data, candidate structure might include lags, differences, ratios, periodicity, nonlinear transforms, cross-channel relationships, state transitions, piecewise rules, or other data-type-specific operations. For other data types, the hypothesis space would change.

The core question is:

> **Can a generalized system discover the smallest reusable computational structure capable of generating, reconstructing, or predicting observations of a system?**

A possible representation of such a discovered structure is not necessarily one equation. It could be a small program, graph, relational dynamical system, symbolic rule set, neural representation, or hybrid. The research objective should determine the mechanism rather than assuming the mechanism in advance.

This yields a useful architectural principle:

> **Representation-discovery mechanism is not part of the North Star.**

Symbolic methods, neural networks, graphs, programs, dynamical systems, or hybrids should be treated as competing hypothesis-space mechanisms. A neural network is justified only when the structure being sought requires the expressive capacity or search behavior it provides.

## Context, Information Leakage, and the Reconstruction Boundary

A further insight emerged from considering generalized prediction in humans and artificial systems: an observer may have access to far more information than is explicitly labeled as “input.” Surrounding context can strongly constrain an unobserved variable.

Therefore:

> **The apparent information available to an observer may be much larger than the explicitly measured input because surrounding structure can implicitly encode constraints on the target.**

This does not mean a predictor can recover arbitrary missing information. If the hidden variable is genuinely independent of the observed context, there is no structural route to reconstruct it. Prediction can recover information that is sufficiently constrained by the observable structure; it cannot conjure independent information from nothing.

This makes **information boundary** a fundamental research concern rather than merely an implementation detail:

`observable context → implicit constraints → reconstructable information`

versus

`observable context ⟂ hidden variable → no reconstructive path`

A useful future experiment would deliberately hide part of a dataset, progressively remove contextual structure, and measure reconstruction quality. The result would define a **reconstruction frontier**: how much surrounding structure must persist before the hidden information becomes reliably recoverable?

This directly connects to E36/E37 information-boundary concerns and to the original compression objective.

## Minimum Retained Structure / Reconstruction Frontier

A particularly clean formulation emerging from the combined archaeology is:

> **What is the minimum surrounding structure that still uniquely determines the data we care about?**

Conceptually:

`more context retained → better reconstruction → threshold → sufficient persistent structure → reconstruction failure`

The retained structure does not have to contain the original data directly. It may contain relationships, constraints, or a generator that makes the original data recoverable.

This may provide a more general experimental framework than “compression ratio.” Instead of only measuring how many bytes were stored, measure how much persistent structure is required to maintain a specified reconstruction or prediction guarantee.

## Research Process as an Analogy

The project itself has become an example of the problem. The raw experiments are observations; the research log preserves relationships between observations, hypotheses, decisions, and changed interpretations. When a new observation changes the interpretation of an old one, the goal is to update the persistent relational structure rather than discard the old observation.

This is useful as an analogy, not as evidence that the research process literally implements the same mechanism as a biological or artificial observer.

## E18–E22: Functional and Relational Turn

E18 explicitly compared optimizing a held-out latent for factor/weight MSE against optimizing it for the function of the recovered Q projection. The constructor remained fixed, so the experiment isolated the effect of the latent objective.

E19 then pushed the objective into **relational attention**, comparing candidate Q behavior against Q/K/V attention context rather than treating the target weight only as an isolated tensor. E20 continued this as a confirmation experiment, while E21 and E22 explored extreme latent capacity and relational capacity.

This is an important historical precursor to the present relational view: the project began asking whether preserving a component's **functional relationships** could matter more than minimizing raw parameter error before the later E36/E37 persistent-memory experiments made relations explicit.

## E23–E30: Latent Geometry Investigation

E23–E30 moved into L2 latent landscapes, coordinate geometry, eigenvector sweeps, cross-seed replication, geometry/behavior sensitivity, rotated geometry, principal directions, rotation invariance, and seed-regime clustering.

The durable conclusion is not that a particular latent coordinate system was discovered. Rather, these experiments established that structured geometry could be real and reproducible enough to investigate, while its exact orientation and behavioral interpretation could vary across seeds. That uncertainty motivated the later shift toward invariants and observation dependence.

## E36 — Local Observer / Adaptive Information Memory

E36 tests whether a moving observer can build useful persistent knowledge from only locally visible information instead of receiving the whole world. Memory can update existing chunks, create new chunks, and merge compatible chunks. The experiment compares persistent knowledge cost with raw observation cost and asks whether information topology can emerge from traversal rather than being imposed.

The later relational E36 version strengthens the boundary: memory receives relative positions, local features, observer motion, and rotation changes, but not absolute world coordinates, world identifiers, or hidden geometry. It retains sparse relations between persistent local anchors and tests reuse across repeated traversal.

## E37 — Minimal Persistent Relational Structure

E37 makes the current question explicit in an interpretable, non-neural baseline. It separates simulator knowledge from observer input and asks whether structure learned on one traversal can explain a second traversal with a different starting phase or direction.

It measures reconstruction, next-observation prediction, structure cost, reuse, ablations, and a relation-budget frontier.

The important progression is:

`E36: can persistent structure emerge?`

`E37: is persistent structure sufficient, and how much relational structure is necessary?`

The E37 result currently suggests that persistent units can preserve reconstructive information while relations provide the missing predictive structure. This should remain framed as evidence within the tested representation and cost model, not as proof of a universal minimum.

## Important Methodological Insight

A recurring failure mode is mistaking experimental machinery for the research question.

For example:

`geometry → rotation → transformed direction → latent intervention → model output → behavior metric`

may validate plumbing without resolving the scientific question.

Always distinguish:

**Is the experimental plumbing correct?**

from:

**What new uncertainty does this experiment remove?**

A technically clean experiment that does not discriminate between hypotheses may be less valuable than a simpler experiment that destroys a competing explanation.

## Architectural Context

A recurring engineering instinct in the project is:

> Build the smallest general mechanism once, then allow many different things to pass through it rather than encoding each case separately.

In the research context this becomes a scientific question: what reusable mechanism can explain a family of observations without separately encoding each observation?

Implementation language is secondary. Python, C#, C++, or another language is an implementation detail, not the conceptual architecture.

More strongly, **the discovery mechanism itself should not be assumed in advance**. Symbolic regression, neural networks, graphs, programs, dynamical systems, or hybrids are candidate mechanisms for searching or representing structure. The research question is the structure that survives, not the technology used to find it.

## Research Hygiene

Do not silently turn a metaphor into a technical definition. Reconstruct the operation or relationship being described before correcting vocabulary.

Do not treat repeated experiments as automatically redundant. A repeated-looking experiment may test a different projection, viewpoint, traversal, representation, observation basis, or invariant.

Do not rerun an experiment merely because it is familiar. State what uncertainty the new version removes.

Do not confuse a good reconstruction score with discovery of the underlying structure. Audit information pathways and ask whether the system could succeed without discovering the intended reusable structure.

Do not confuse representation similarity with information sufficiency. A representation that looks numerically unlike the target may still contain sufficient constraints for exact reconstruction.

When using physical analogies, preserve the operational mapping. Mechanical rotation should not be substituted for a change in observation basis if the latter is the actual research variable.

When evaluating “missing information,” audit contextual leakage first. A hidden value may be inferable because its generating structure is present in the observed context.

# Neural Compression — Canonical Audit Summary

**Audit date:** 2026-09-10  
**Status:** Partial but high-confidence reconstruction of the major experimental lineage. This file is intended to be the canonical project-context handoff and should be updated as the remaining archaeology is completed.

## Core scientific question

Where does the information required for neural behavior actually live, and how small can the variable representation become if shared machinery captures reusable structure?

The project began as neural-weight compression, but the experiments increasingly distinguish raw numerical weight reconstruction from preservation of function/behavior. The recurring hypothesis is that useful behavior may be represented by a much smaller state than the original parameter tensor, provided the representation is interpreted by shared machinery and trained against the right objective.

## Most important correction from the audit

The project has **already built an integrated latent-native language-model prototype**. The next serious question is therefore not merely whether the pieces can be assembled, but whether the architecture produces a scaling advantage against appropriate dense and direct-low-rank controls.

The latent-transformer branch uses tiny per-structure latent variables plus shared constructor machinery to generate low-rank MLP structure inside a functioning decoder language model. A large architecture sweep was run around this design. The next step should treat that as version zero rather than restarting component discovery.

## High-confidence findings

### 1. Weight-space fidelity and behavioral fidelity are not the same objective

Across the project, better numerical reconstruction does not reliably imply better behavioral reconstruction. This motivated activation/behavior-aware objectives.

A particularly strong controlled result is the activation-aware low-rank factorization comparison against ordinary truncated SVD at the same rank/storage budget. At rank 64, activation-aware variants reduced logit RMSE from roughly 0.0655 for SVD to roughly 0.0416–0.0435. At rank 128, all three activation-aware runs recovered 24/24 held-out continuations while the SVD control recovered 23/24. Calibration and evaluation prompts were separated.

**Working conclusion:** If the goal is to preserve what the model does, the states/directions actually used by the model can be a better optimization target than raw matrix error.

### 2. Latent dimensionality is often not the primary bottleneck

Several experiments pushed latent capacity down to one or two dimensions and later swept it upward. Larger latent dimensionality frequently produced little or no reproducible held-out behavioral gain.

**Working conclusion:** Stop treating “how few latent scalars can we use?” as the main research question. The more important variables appear to be the shared constructor/interpreter, relational structure, and training objective.

### 3. Decoder/constructor memorization is a real confound

Early spectacular tiny-latent reconstructions demonstrated that a tiny code can select/reconstruct useful behavior, but a target-specific decoder can absorb a large amount of information. Cross-target/shared-constructor experiments weakened the apparent magic substantially.

**Working conclusion:** A tiny latent is scientifically/economically interesting only when its constructor is genuinely shared and amortized across many targets/structures. Always account for constructor size.

### 4. Generic relational machinery is not automatically sufficient

E15/E16 tested pooled relational and true pairwise-attention variants. They did not automatically solve held-out generalization.

**Working conclusion:** Retire the simple claim “add relational attention and generalization appears.” Relations matter only when the task/representation forces useful relational information to be carried.

### 5. Later persistent-relational experiments show a cleaner relational effect

E37 (MPRS traversal invariance) deliberately withheld absolute world coordinates, world indices, hidden geometry, position-derived features, and future observations from memory.

Full relational condition:
- final units: 160
- final relations: 128
- mean pass-2 reconstruction error: ~0.1717
- mean pass-2 prediction F1: ~0.5534
- mean pass-2 prediction position error: ~0.3818

No-relations ablation:
- same 160 units
- reconstruction error remained ~0.1717
- prediction F1 collapsed to 0
- prediction position error became 1.0

The minimum-structure sweep showed a dose-response relationship. With 64 retained relations, prediction F1 reached ~0.5156 and position error ~0.3365; larger relation sets continued improving prediction.

**Working conclusion:** In this synthetic traversal system, local units can preserve/reconstruct observations while relations carry information required to predict how those observations connect across traversal/time. This is a real ablation result, although it does not by itself establish the same mechanism in language models.

### 6. Persistent relational concept memory is promising but unstable

E41 has multiple configurations/seeds. Some runs improve genuinely ambiguous/homonym queries as relational context increases; others degrade. Identity persistence can remain extremely high while relational neighborhoods change.

**Classification:** SUPPORTED MECHANISM / UNSTABLE IMPLEMENTATION.

Do not cherry-pick the successful E41 runs. The aggregate says there is useful signal, but the formulation is not yet robust enough to call solved.

### 7. Latent geometry is real locally, but semantic interpretation is not simple

The E24–E29 family found anisotropic local latent geometry: preferred and insensitive directions occur. E28 then showed that curvature/ridge direction does not map cleanly or universally onto behavioral importance across seeds. E29 established coordinate/rotation invariance of the mathematical geometry.

**Classification:**
- Local anisotropic geometry: SHOWN.
- Universal meaningful latent axes: NOT SHOWN.
- More coordinate-rotation sanity tests: RETIRED unless a new hypothesis requires them.

### 8. Exact learned compression can amortize model overhead

The Test9 lossless-compression branch eventually beat zlib on sufficiently large source-code inputs while including model overhead. It lost badly at small sizes, approached break-even as the predictor was amortized, and became advantageous at larger inputs.

Test10 tightened methodology: held-out data separation, integer range coding driven by the learned probabilities, identical causal encoder/decoder state, SHA-256 reconstruction checks, and explicit model/metadata cost. A definitive final Test10 measurement artifact has not yet been located in this audit, so Test10 remains OPEN rather than being counted as a win.

**Working conclusion:** Shared learned structure can be initially expensive while per-instance representation becomes cheap enough for amortization to matter. This pattern is conceptually consistent with the shared-constructor neural experiments.

### 9. The original 24-prompt behavioral suite had measurement dead zones

Later auditing found that some prompts were insensitive floors (the model still answered correctly when the target projection was zeroed/randomized), while others were effectively unreachable ceilings (even strong high-rank approximations failed). The active suite was expanded to target sensitive prompts more deliberately.

**Working conclusion:** Early exact-count results such as 12/24 versus 15/24 are useful but crude. Prefer sensitive-prompt and continuous logit/activation metrics for new work.

## Important negative/boundary results

- E18: a simple functional latent objective did not consistently outperform weight-MSE optimization; one seed was materially worse. Retire the blanket claim that a functional objective is automatically better.
- E15/E16: pooled relation features and pairwise attention did not automatically solve held-out reconstruction/generalization.
- E28: latent Hessian/ridge geometry does not universally predict behavioral importance.
- E30: technical failure/incomplete artifact; do not interpret as scientific evidence.
- E41: relational context effects vary by seed/configuration; promising but not robust.

Negative results are part of the project map, not failures to remember.

## Current synthesis

The strongest recurring picture is:

1. Useful function can occupy a much smaller effective representation than raw parameter space suggests.
2. Exact numerical weight reconstruction is often less important than preserving behavior on the states the model actually visits.
3. Making the latent larger frequently matters less than improving the shared machinery that interprets it.
4. Tiny-code claims must include/amortize constructor cost; otherwise information has merely moved into the decoder.
5. Relational structure can carry predictive information that local item representations alone do not, at least in controlled synthetic systems.
6. These ideas can already be assembled into a functioning latent/shared-constructor language model.

## Recommended next major experiment

Do **not** make E41, more geometry work, compressed LayerNorms, whole-model reconstruction, or another exotic latent mechanism prerequisites.

Freeze most of a conventional transformer architecture:
- conventional embeddings
- conventional residual stream
- conventional normalization
- conventional attention

Make the experimental component the part with the strongest accumulated evidence:

**tiny per-structure latent → shared constructor → generated low-rank MLP structure**

Include activation/behavior-aware training where justified by the controlled compression results.

Train three matched families:
1. ordinary dense transformer
2. direct low-rank transformer
3. latent/shared-constructor transformer

Match data, tokenizer, optimization budget, seeds, and as closely as possible compute/parameter accounting. Scale through several model/data sizes. Measure validation loss/perplexity, training throughput, inference throughput, active parameter/state bytes, checkpoint bytes, constructor amortization, memory, and long-context/behavioral tests.

The central question is now:

> Does the latent/shared-constructor representation improve language-learning efficiency per parameter, byte, or unit compute as scale increases?

If yes, characterize the scaling law and failure boundaries. If no, identify where the integrated hypothesis breaks.

# Neural Compression — Project Status Summary

Date: 2026-09-10

This document captures the current working interpretation of the Neural Compression project after a broad review of the repository, Library artifacts, experiment summaries, and historical discussion. It is intentionally a research-status document, not a claim of novelty or a publication-ready result.

## Current high-level conclusion

The project is no longer best described as a collection of unrelated compression experiments. The main line has converged on a coherent question:

> How much of a neural system's useful function can be represented by a much smaller state, when shared machinery interprets that state and the training objective is allowed to care about behavior rather than exact parameter reconstruction?

The strongest recurring result is that exact numerical weight reconstruction is often a poor proxy for preserving useful behavior. Shared constructor cost, relational structure, and the objective used to define equivalence matter at least as much as raw latent dimensionality.

## Major findings so far

### 1. Behavior-aware / activation-aware compression beats plain SVD at the same rank in the tested Q-projection setting

Historical experiment summary:

- Rank 64 (~7x factor storage compression): truncated SVD logit RMSE ~0.06549; activation-aware runs ~0.04162–0.04354.
- Rank 128 (~3.5x): activation-aware runs reached 24/24 exact held-out continuations across 3 runs, with lower logit RMSE than the SVD control; SVD reached 23/24 in that summary.
- Calibration and evaluation prompt sets were separated.

Interpretation: directions used by the model's actual behavior can be more compressible than raw matrix error suggests. This supports carrying functional/activation-aware objectives into future model designs.

### 2. Increasing latent dimensionality often matters less than expected

Across shared-constructor sweeps, moving from L1/L2 to L4/L8 frequently produced little or no reproducible behavioral gain. Tiny latents can retain surprisingly large fractions of behavior, but this should not be interpreted as the latent alone containing the whole model.

Working conclusion: stop treating `How tiny can Z be?` as the central question. The more important questions are how Z is interpreted, whether shared machinery generalizes, and what objective trains the representation.

### 3. Target-specific constructors can hide information

Some spectacular tiny-latent reconstruction results were confounded by the capacity of the constructor/decoder. A tiny latent is not a tiny standalone model when a large decoder is specialized to one target.

This motivated cross-target/shared-constructor tests and remains a core accounting rule:

> Shared machinery must be amortized across many targets/structures before tiny per-instance latents become meaningful compression.

### 4. Simple relational layers were not automatically sufficient

Early pooled and pairwise relational constructor experiments did not reliably improve held-out functional reconstruction. This is a useful negative result: merely adding relational communication does not solve generalization.

### 5. Relational structure can carry predictive information that local units alone do not

E37 (MPRS traversal invariance) is one of the clearest mechanistic results.

The memory system was not given absolute world coordinates, world indices, hidden geometry, position-derived features, or future observations.

Full relational condition:
- mean pass-2 reconstruction error: ~0.1717
- mean pass-2 prediction F1: ~0.5534
- mean pass-2 prediction position error: ~0.3818

No-relations condition:
- reconstruction error remained ~0.1717
- prediction F1 collapsed to 0.0
- prediction position error went to 1.0

A relation-retention sweep showed a dose-response improvement in predictive performance; 64 retained relations crossed the experiment's stated sufficiency thresholds (F1 ~0.5156, position error ~0.3365).

Interpretation: in this synthetic system, local units were sufficient for observation reconstruction, while relations carried information needed for traversal/prediction.

### 6. Persistent relational concept memory is promising but unstable

E41 variants show mixed results.

Some configurations improve genuinely ambiguous masked-homonym prediction with increasing relational context (for example ~0.389 -> ~0.497 in one run; ~0.234 -> ~0.306 in another), while other configurations degrade the same metric.

Alias identity often remains very strong, but robust generalization of relational memory has not yet been established.

Status: `SUPPORTED MECHANISM / UNSTABLE IMPLEMENTATION`.

### 7. Latent geometry exists, but simple "geometry = meaning" stories failed

L2 geometry studies repeatedly found anisotropic local landscapes, principal directions, ridges/valleys, and coordinate-invariant local structure. However, the relationship between curvature and behavior varied by seed and sometimes inverted.

Working conclusion:
- local latent geometry exists: supported
- universal semantic axes: not shown
- more rotation/invariance sanity checks: low priority / largely retired

### 8. The project already contains a functioning latent-native language-model branch

A major correction to prior planning: the project has already built small working language models using the shared-constructor / latent-weight idea. Therefore the next major question is not `Can this be made into a language model?`

It is:

> Does this architecture produce a scaling or efficiency advantage over strong conventional and direct-low-rank controls?

## Compression branch

The causal neural compression work is also more mature than sometimes remembered.

- The system uses a neural probability model with an exact entropy coder.
- Encoder and decoder reproduce the same causal state.
- Exact reconstruction and SHA-256 parity are required in the corrected Test10 lineage.
- Model + payload + metadata cost is explicitly counted.
- Earlier scaling work showed learned shared structure can lose badly at small inputs because model cost dominates, then become competitive or better once the predictor is amortized over enough data.

A definitive final Test10 measurement artifact still needs to be located/classified before making a strong claim about that branch.

## Important methodological correction: the original 24-prompt suite had dead zones

The original behavioral benchmark mixed:

- insensitive floor prompts (still correct even with the target projection zeroed/randomized),
- unsolvable ceiling prompts (not recovered even by high-quality low-rank baselines), and
- genuinely discriminating prompts.

A later active test suite explicitly separated these categories and expanded evaluation toward high-sensitivity prompts. Early exact-count results should therefore be treated as useful but coarse measurements rather than definitive functional scores.

## Current model-building recommendation

Do not make persistent memory, exotic geometry, compressed normalization, or whole-model reconstruction prerequisites for the next serious model.

For the next scaling study, keep most transformer machinery conventional and isolate the experimentally supported idea:

- conventional embeddings / residual stream / normalization / attention,
- tiny per-structure latent state,
- shared constructor,
- generated low-rank MLP structure,
- functional / activation-aware training signal where appropriate.

Compare against at least:

1. conventional dense transformer,
2. direct low-rank parameterized transformer at comparable trainable/storage budget,
3. shared-constructor latent transformer.

Train on enough diverse data that the dense control is not simply overfitting, use multiple seeds and model sizes, and compare loss/perplexity versus parameter count, serialized bytes, training compute, and inference compute.

The decisive open question is now:

> Does shared-constructor latent parameterization have a better scaling curve, parameter efficiency, or storage/function tradeoff than ordinary parameterization?

# Research Log Addendum — 2026-08-27

## Decision: Stop Asking Only Questions; Build the Reusable Mechanism

After reviewing the recovered ROCM-test history, E14B, E18–E30, E36, and E37, the current assessment changed from “continue isolating the phenomenon” to “we have enough evidence to build the mechanism suggested by the evidence.”

This is not a claim of novelty, a breakthrough, or a universal theory. It is a change in research posture: the project has accumulated enough convergent observations that another round of increasingly similar diagnostic experiments risks producing diminishing returns without giving us a usable artifact.

### What the accumulated evidence now supports

The project repeatedly encountered the same structural pattern through different implementations:

`observation → compact local representation → persistence → reuse → relationships → prediction/reconstruction`

The early neural compressor demonstrated a particularly concrete version of persistence: encoder and decoder can maintain synchronized adaptive state because both reconstruct the same state trajectory from shared history.

E14B demonstrated the instinct to represent a large system as addressable local pieces rather than one monolithic representation.

The functional-latent experiments showed that strong behavioral reconstruction can coexist with poor parameter-level similarity, weakening the assumption that useful compression must preserve the original representation directly.

E36 made persistent local units and relations explicit under an information boundary.

E37 then supplied the strongest current evidence for the relational component: in its tested synthetic environment, reconstruction remained essentially unchanged while prediction improved as relational structure was retained. The reported relation-budget curve rose from zero prediction F1 with no relations to approximately 0.52 at sixty-four retained relations and approximately 0.61 at one hundred twenty-eight, while reconstruction error remained approximately 0.172. The full relational condition also achieved approximately 0.55 prediction F1 while the no-relations condition achieved zero.

These results do not prove that relations are universally necessary, nor that the tested number of relations is a true global minimum. They do establish that, in the tested setup, relational information carried predictive information that local reconstruction alone did not.

### New working hypothesis

> A compact persistent representation may be more useful when it preserves reusable relationships between local observations than when it independently preserves each observation.

This is now considered sufficiently supported to justify implementation as a reusable system component.

### New implementation direction

Build a minimal, inspectable persistent relational memory system rather than immediately adding another large neural experiment.

The first implementation should:

`observe → identify local unit → persist/update unit → record sparse relation → predict → compare → update`

The observer must not receive world IDs, absolute world coordinates, hidden geometry, or future observations. The simulator may know those things for evaluation, but the memory must not.

The first useful artifact should be small enough to inspect and run quickly. It should create persistent units from local observations, reuse units across a changed observation/traversal, maintain a sparse relational graph, and make predictions from that graph.

### Why build now

The research has reached a point where an artifact can provide more information than another isolated sweep. A reusable mechanism gives us something that can be placed in different environments, visualized, instrumented, and compared against simpler alternatives.

The goal is therefore no longer “prove the hypothesis before building anything.” The goal is “build the smallest falsifiable implementation of the hypothesis and let its behavior generate the next questions.”

### Guardrail

The artifact is not itself evidence that the hypothesis is correct. It is a testable implementation of the current model.

If it fails, inspect which assumption failed.

If it works only on the toy world, record that limitation.

If it generalizes to substantially different observations while maintaining a compact persistent structure, that becomes materially more interesting.

If it produces behavior we did not design for, preserve the result before explaining it.

### Current research posture

We have enough evidence to build.

We do not yet have enough evidence to claim universality.

That distinction is deliberate.

# Latent Transformer v0

This folder turns the neural-compression latent/shared-constructor work into a language model that trains from random initialization.

The experiment compares three MLP parameterizations inside the same tiny decoder-only transformer:

- `dense`: ordinary dense MLP matrices.
- `lowrank`: each MLP matrix directly owns trainable `L` and `R` factors, with `W = L @ R`.
- `latent`: each MLP matrix owns only a small latent vector `z` (plus one scalar gain). One shared coordinate constructor generates `L` and `R` on demand. The full dense MLP matrix is never an independently learned or serialized parameter.

Attention, embeddings, RMSNorm, residual structure, loss, tokenizer, and training loop are intentionally conventional. v0 changes only the MLP parameter representation so failure/success is interpretable.

## Why the constructor is coordinate-based

A naive hypernetwork whose last layer outputs every factor value can hide the storage cost inside a giant decoder. v0 avoids that. The shared constructor receives:

`latent + matrix-type embedding + fixed Fourier coordinate features`

and produces one rank-dimensional factor row/column. Its parameter count therefore does not scale directly with `d_model`, `d_ff`, or number of transformer layers.

For a latent matrix:

`z -> shared constructor -> (L, R)`

and execution is direct through the factors:

`y = (x @ R.T) @ L.T`

No dense `W` has to be materialized.

## First test

Requires PyTorch 2.x. The tokenizer is byte-level (`vocab_size=256`) so no tokenizer package or pretrained model is needed.

Quick plumbing test:

```bash
python latent_transformer_v0.py --smoke-test --mode latent --steps 50
```

Train on any UTF-8 text corpus:

```bash

  --device auto \

```

Run the controls with the same settings:

Default model geometry is 6 layers, `d_model=384`, 6 heads, `d_ff=1536`, context 256, factor rank 64, latent dimension 32.

## Outputs

Each run writes a separate directory under `runs/latent_transformer_v0/` containing:

- `model.pt` — checkpoint
- `report.json` — configuration, parameter accounting, loss/perplexity history, throughput, and peak CUDA/ROCm allocation when available
- `sample.txt` — greedy byte-level sample

The report separates total parameters, constructor parameters, per-matrix latent state, MLP parameters, attention parameters, and other parameters.

## What counts as success in v0

The first question is deliberately narrow: **can the latent-generated model learn language with a normal-looking loss curve?**

If it can, the next experiments should sweep latent dimension and factor rank under identical data/training budgets, then compare validation loss, checkpoint bytes, optimizer memory, peak device memory, and tokens/sec against `dense` and `lowrank`.

The `lowrank` control matters: if `latent` only matches the gains of direct low-rank factors, the improvement is factorization rather than the shared latent representation. If `latent` can retain quality while using much less matrix-specific persistent state, the shared constructor is contributing something additional.

# Persistent Structure

**Persistent Structure** is an experimental research project investigating how much of the information required to explain or reconstruct observations can be represented by a smaller, reusable structure rather than by storing every parameter or observation directly.

The project began as an exploration of neural-weight compression. Over time, the research shifted toward a broader question:

> What is the smallest persistent relational structure capable of explaining multiple observations of the same underlying system?

The current research direction is especially interested in tiny per-structure latent representations, shared constructors, low-rank generated structure, and persistent relational information.

## What this repository is

This is a research archive and experimental codebase, not a finished architecture or a claim of a solved compression problem.

The repository preserves experiments, controls, negative results, research notes, prototypes, and the reasoning that led from one experiment to the next. Some experiments are exploratory or incomplete. That is intentional: the history is part of the research record.

The strongest current question is:

> Does a latent/shared-constructor representation improve language-learning efficiency per parameter, byte, or unit compute as scale increases?

The project has already produced an integrated latent-native language-model prototype. The next meaningful test is not whether the individual pieces can work, but whether the combined representation produces a measurable advantage against appropriately matched dense and direct-low-rank controls.

## Current research picture

The experiments provide several useful pieces of evidence, with important limits.

Behavioral fidelity is not always the same thing as weight-space fidelity. Activation-aware low-rank factorization produced lower logit reconstruction error than truncated SVD at the same rank in a controlled comparison, and at one tested rank recovered all held-out continuations in the reported runs.

Very small latent representations can retain useful behavior in some settings. However, the experiments also showed that a target-specific decoder can hide information in the constructor. A tiny latent is therefore only interesting when the machinery interpreting it is genuinely shared and its cost is properly accounted for.

Persistent relational experiments provide evidence that relationships between local units can carry predictive information that the local units alone do not contain in controlled synthetic systems. The persistent relational concept-memory experiments are promising but unstable across seeds and configurations, so they are not presented here as a solved mechanism.

The project also found local anisotropic geometry in latent spaces. Later experiments showed that this geometry does not automatically provide a universal semantic coordinate system or a universal predictor of behavioral importance.

The lossless-compression branch further demonstrated that learned shared predictive structure can become economical when its fixed model cost is amortized over sufficiently large inputs. This is a useful engineering result, but it does not by itself establish that the same mechanism produces a better neural representation.

These distinctions matter. The repository deliberately records both positive and negative results.

## Research lineage

The project developed through several stages:

neural weight compression -> behavioral/activation-aware compression -> tiny latent representations -> shared constructors -> relational representations -> persistent relational structure -> latent/shared-constructor language models.

The original repository name, neural_compression, is retained as historical provenance. The research title is now **Persistent Structure**.

See ORIGIN.md for the project's conceptual lineage.

See NEURAL_COMPRESSION_AUDIT.md for the current reconstructed state of the research and its evidence boundaries.

See RESEARCH_LOG.md for the evolving research record.

## Important negative results

The project does not claim that every proposed mechanism worked.

A simple functional latent objective did not consistently outperform weight-MSE optimization.

Generic relational attention did not automatically produce held-out generalization.

Latent curvature or ridge directions did not universally predict behavioral importance.

Some persistent relational memory configurations improved ambiguous queries while others degraded them.

Early behavioral evaluations also contained insensitive prompts, which led to a stronger emphasis on continuous logit and activation metrics.

These results narrowed the research question and changed what experiments were pursued next.

## Reproducing the work

The repository contains many historical experiments with different dependencies, datasets, configurations, and hardware assumptions. There is not yet a single one-command reproduction environment for the entire archive.

Experiment-specific scripts and documentation should be treated as the authoritative source for reproducing individual results.

Where a result has not been fully replicated or an artifact is missing, the repository attempts to say so explicitly rather than presenting it as established.

## Status

This is an experimental research release.

It should be read as a documented body of work and a set of testable hypotheses, not as a production compression library, a proven replacement for conventional transformers, or evidence for claims outside the experiments themselves.

The next major experiment proposed by the current audit is a matched comparison between:

- an ordinary dense transformer,
- a direct low-rank transformer,
- and a latent/shared-constructor transformer using tiny per-structure latents and generated low-rank MLP structure.

The comparison should match data, tokenizer, optimization budget, seeds, and compute accounting as closely as practical, and measure validation loss/perplexity, throughput, active state bytes, checkpoint bytes, constructor amortization, memory, and behavioral performance.

# Neural Memory Network

This branch is a clean implementation track derived from the Neural Compression research.

## Why this exists

The parent research repeatedly explored persistent state, local representations, relationships between local units, and compact descriptions of change. The purpose of this branch is to stop treating those ideas only as experiments and try to assemble them into a usable system.

## Working hypothesis

A distributed collection of small persistent models or memory units may be able to answer queries by communicating compact state changes rather than repeatedly exchanging complete states.

Conceptually:

    query -> local memory -> delta -> local memory -> delta -> ... -> answer

A synchronized reference state may allow two units to communicate only what changed, building on the earlier Neural Compression experiments.

## First implementation goals

1. Represent one persistent local memory independently.
2. Establish a compact state-delta format between synchronized peers.
3. Verify that a receiver can apply a delta and recover the sender's state/behavior.
4. Extend to multiple memories and query propagation.
5. Measure useful behavior, memory growth, communication cost, and propagation depth.

## Research rule

This branch is exploratory. A working result is enough reason to build on it. We will investigate failures when they matter, but will not spend experiments eliminating hypothetical ambiguities that do not change the next engineering decision.

def load_bytes(path: Optional[Path], smoke: bool) -> Tensor:
    if smoke:
        raw = SMOKE_CORPUS
    else:
        if path is None:
            raise SystemExit("Pass --data FILE, or use --smoke-test.")
        raw = path.read_bytes()
    if len(raw) < 4096:
        raise SystemExit(f"Corpus is too small ({len(raw):,} bytes); need at least 4 KiB.")
    return torch.tensor(list(raw), dtype=torch.long)


def split_data(data: Tensor, fraction: float = 0.9) -> Tuple[Tensor, Tensor]:
    cut = max(1, min(data.numel() - 1, int(data.numel() * fraction)))
    return data[:cut], data[cut:]


def sample_batch(data: Tensor, batch_size: int, context: int, device: torch.device) -> Tuple[Tensor, Tensor]:
    if data.numel() <= context + 1:
        raise ValueError(f"split has {data.numel()} bytes but context={context}")
    starts = torch.randint(0, data.numel() - context - 1, (batch_size,))
    x = torch.stack([data[i:i + context] for i in starts.tolist()])
    y = torch.stack([data[i + 1:i + context + 1] for i in starts.tolist()])
    return x.to(device, non_blocking=True), y.to(device, non_blocking=True)


class RMSNorm(nn.Module):
    def __init__(self, dim: int, eps: float = 1e-5):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(dim))
        self.eps = eps

    def forward(self, x: Tensor) -> Tensor:
        rms = x.float().pow(2).mean(dim=-1, keepdim=True).add(self.eps).rsqrt().to(x.dtype)
        return x * rms * self.weight


class CausalSelfAttention(nn.Module):
    def __init__(self, cfg: ModelConfig):
        super().__init__()
        if cfg.d_model % cfg.n_heads:
            raise ValueError("d_model must be divisible by n_heads")
        self.n_heads = cfg.n_heads
        self.head_dim = cfg.d_model // cfg.n_heads
        self.dropout = cfg.dropout
        self.qkv = nn.Linear(cfg.d_model, 3 * cfg.d_model, bias=False)
        self.out = nn.Linear(cfg.d_model, cfg.d_model, bias=False)

    def forward(self, x: Tensor) -> Tensor:
        b, t, c = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = q.view(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        k = k.view(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        v = v.view(b, t, self.n_heads, self.head_dim).transpose(1, 2)
        y = F.scaled_dot_product_attention(
            q, k, v,
            attn_mask=None,
            dropout_p=self.dropout if self.training else 0.0,
            is_causal=True,
        )
        y = y.transpose(1, 2).contiguous().view(b, t, c)
        return self.out(y)


class LowRankLinear(nn.Module):
    """y = (x @ R.T) @ L.T, with W = L @ R."""
    def __init__(self, in_features: int, out_features: int, rank: int):
        super().__init__()
        rank = min(rank, in_features, out_features)
        self.in_features = in_features
        self.out_features = out_features
        self.rank = rank
        self.R = nn.Parameter(torch.empty(rank, in_features))
        self.L = nn.Parameter(torch.empty(out_features, rank))
        nn.init.kaiming_uniform_(self.R, a=math.sqrt(5))
        nn.init.normal_(self.L, mean=0.0, std=0.02 / math.sqrt(max(1, rank)))

    def forward(self, x: Tensor) -> Tensor:
        return F.linear(F.linear(x, self.R), self.L)


class CoordinateFactorConstructor(nn.Module):
    """
    ONE shared hypernetwork for all latent MLP matrices.

    It never has an output layer proportional to matrix size. Instead it maps
    (latent code, matrix-type embedding, coordinate Fourier features) -> one
    rank-dimensional row/column at a time. Thus constructor parameter count is
    independent of d_model, d_ff, and layer count.
    """
    def __init__(self, latent_dim: int, rank: int, hidden: int,
                 type_dim: int, fourier_bands: int, n_types: int = 3):
        super().__init__()
        self.latent_dim = latent_dim
        self.rank = rank
        self.fourier_bands = fourier_bands
        self.type_embed = nn.Embedding(n_types, type_dim)
        coord_dim = 1 + 2 * fourier_bands
        in_dim = latent_dim + type_dim + coord_dim

        def make_net() -> nn.Sequential:
            net = nn.Sequential(
                nn.Linear(in_dim, hidden), nn.SiLU(),
                nn.Linear(hidden, hidden), nn.SiLU(),
                nn.Linear(hidden, rank),
            )
            nn.init.normal_(net[-1].weight, std=0.002)
            nn.init.zeros_(net[-1].bias)
            return net

        self.row_net = make_net()
        self.col_net = make_net()

    def coord_features(self, n: int, *, device: torch.device, dtype: torch.dtype) -> Tensor:
        x = torch.linspace(-1.0, 1.0, n, device=device, dtype=dtype).unsqueeze(1)
        feats = [x]
        for k in range(self.fourier_bands):
            f = math.pi * (2.0 ** k)
            feats.extend((torch.sin(f * x), torch.cos(f * x)))
        return torch.cat(feats, dim=1)

    def _inputs(self, z: Tensor, type_id: int, n: int) -> Tensor:
        dtype = z.dtype
        device = z.device
        coords = self.coord_features(n, device=device, dtype=dtype)
        z_rep = z.reshape(1, -1).expand(n, -1)
        type_tensor = torch.tensor(type_id, device=device, dtype=torch.long)
        e = self.type_embed(type_tensor).to(dtype).reshape(1, -1).expand(n, -1)
        return torch.cat((z_rep, e, coords), dim=1)

    def factors(self, z: Tensor, type_id: int,
                in_features: int, out_features: int) -> Tuple[Tensor, Tensor]:
        L = self.row_net(self._inputs(z, type_id, out_features))
        R_cols = self.col_net(self._inputs(z, type_id, in_features))
        R = R_cols.transpose(0, 1).contiguous()
        scale = 1.0 / math.sqrt(max(1, self.rank))
        return L * scale, R


class LatentLinear(nn.Module):
    """A matrix whose only matrix-specific trainable state is z (+ one gain)."""
    def __init__(self, in_features: int, out_features: int,
                 latent_dim: int, type_id: int):
        super().__init__()
        self.in_features = in_features
        self.out_features = out_features
        self.type_id = int(type_id)
        self.z = nn.Parameter(torch.randn(latent_dim) * 0.02)
        self.log_gain = nn.Parameter(torch.zeros(()))

    def forward(self, x: Tensor, constructor: CoordinateFactorConstructor) -> Tensor:
        L, R = constructor.factors(self.z, self.type_id, self.in_features, self.out_features)
        return F.linear(F.linear(x, R), L) * self.log_gain.exp()


class DenseMLP(nn.Module):
    def __init__(self, cfg: ModelConfig):
        super().__init__()
        self.gate = nn.Linear(cfg.d_model, cfg.d_ff, bias=False)
        self.up = nn.Linear(cfg.d_model, cfg.d_ff, bias=False)
        self.down = nn.Linear(cfg.d_ff, cfg.d_model, bias=False)

    def forward(self, x: Tensor, constructor=None) -> Tensor:
        return self.down(F.silu(self.gate(x)) * self.up(x))


class LowRankMLP(nn.Module):
    def __init__(self, cfg: ModelConfig):
        super().__init__()
        self.gate = LowRankLinear(cfg.d_model, cfg.d_ff, cfg.rank)
        self.up = LowRankLinear(cfg.d_model, cfg.d_ff, cfg.rank)
        self.down = LowRankLinear(cfg.d_ff, cfg.d_model, cfg.rank)

    def forward(self, x: Tensor, constructor=None) -> Tensor:
        return self.down(F.silu(self.gate(x)) * self.up(x))


class LatentMLP(nn.Module):
    def __init__(self, cfg: ModelConfig):
        super().__init__()
        self.gate = LatentLinear(cfg.d_model, cfg.d_ff, cfg.latent_dim, MATRIX_TYPES["gate"])
        self.up = LatentLinear(cfg.d_model, cfg.d_ff, cfg.latent_dim, MATRIX_TYPES["up"])
        self.down = LatentLinear(cfg.d_ff, cfg.d_model, cfg.latent_dim, MATRIX_TYPES["down"])

    def forward(self, x: Tensor, constructor: CoordinateFactorConstructor) -> Tensor:
        return self.down(F.silu(self.gate(x, constructor)) * self.up(x, constructor), constructor)


class Block(nn.Module):
    def __init__(self, cfg: ModelConfig):
        super().__init__()
        self.norm1 = RMSNorm(cfg.d_model)
        self.attn = CausalSelfAttention(cfg)
        self.norm2 = RMSNorm(cfg.d_model)
        if cfg.mode == "dense":
            self.mlp = DenseMLP(cfg)
        elif cfg.mode == "lowrank":
            self.mlp = LowRankMLP(cfg)
        elif cfg.mode == "latent":
            self.mlp = LatentMLP(cfg)
        else:
            raise ValueError(cfg.mode)

    def forward(self, x: Tensor, constructor: Optional[CoordinateFactorConstructor]) -> Tensor:
        x = x + self.attn(self.norm1(x))
        x = x + self.mlp(self.norm2(x), constructor)
        return x


class TinyLM(nn.Module):
    def __init__(self, cfg: ModelConfig):
        super().__init__()
        self.cfg = cfg
        self.token = nn.Embedding(cfg.vocab_size, cfg.d_model)
        self.position = nn.Embedding(cfg.context, cfg.d_model)
        self.blocks = nn.ModuleList([Block(cfg) for _ in range(cfg.n_layers)])
        self.norm = RMSNorm(cfg.d_model)
        self.lm_head = nn.Linear(cfg.d_model, cfg.vocab_size, bias=False)
        self.lm_head.weight = self.token.weight

        self.constructor: Optional[CoordinateFactorConstructor]
        if cfg.mode == "latent":
            self.constructor = CoordinateFactorConstructor(
                latent_dim=cfg.latent_dim,
                rank=cfg.rank,
                hidden=cfg.constructor_hidden,
                type_dim=cfg.constructor_type_dim,
                fourier_bands=cfg.constructor_fourier_bands,
            )
        else:
            self.constructor = None

        self.apply(self._init_weights)
        if self.constructor is not None:
            for net in (self.constructor.row_net, self.constructor.col_net):
                nn.init.normal_(net[-1].weight, std=0.002)
                nn.init.zeros_(net[-1].bias)

    @staticmethod
    def _init_weights(m: nn.Module) -> None:
        if isinstance(m, nn.Linear):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)
            if m.bias is not None:
                nn.init.zeros_(m.bias)
        elif isinstance(m, nn.Embedding):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)

    def forward(self, idx: Tensor, targets: Optional[Tensor] = None):
        _, t = idx.shape
        if t > self.cfg.context:
            raise ValueError(f"sequence length {t} exceeds context {self.cfg.context}")
        pos = torch.arange(t, device=idx.device)
        x = self.token(idx) + self.position(pos)[None, :, :]
        for block in self.blocks:
            x = block(x, self.constructor)
        logits = self.lm_head(self.norm(x))
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.reshape(-1, logits.size(-1)), targets.reshape(-1))
        return logits, loss

    @torch.no_grad()
    def generate(self, idx: Tensor, max_new_tokens: int) -> Tensor:
        was_training = self.training
        self.eval()
        for _ in range(max_new_tokens):
            crop = idx[:, -self.cfg.context:]
            logits, _ = self(crop)
            next_token = torch.argmax(logits[:, -1, :], dim=-1, keepdim=True)
            idx = torch.cat((idx, next_token), dim=1)
        self.train(was_training)
        return idx


def count_parameters(model: nn.Module) -> Dict[str, int]:
    groups = {"total": 0, "constructor": 0, "latents": 0, "mlp": 0, "attention": 0, "other": 0}
    for name, p in model.named_parameters():
        n = p.numel()
        groups["total"] += n
        if "constructor" in name:
            groups["constructor"] += n
        elif name.endswith(".z") or name.endswith(".log_gain"):
            groups["latents"] += n
        elif ".mlp." in name:
            groups["mlp"] += n
        elif ".attn." in name:
            groups["attention"] += n
        else:
            groups["other"] += n
    return groups


def state_dict_bytes(model: nn.Module) -> int:
    seen = set()
    total = 0
    for t in model.state_dict().values():
        ptr = (t.untyped_storage().data_ptr(), t.untyped_storage().nbytes())
        if ptr not in seen:
            seen.add(ptr)
            total += t.untyped_storage().nbytes()
    return total


def human_bytes(n: int) -> str:
    units = ("B", "KiB", "MiB", "GiB")
    x = float(n)
    for unit in units:
        if x < 1024.0 or unit == units[-1]:
            return f"{x:.2f} {unit}"
        x /= 1024.0
    return f"{x:.2f} GiB"


def choose_device(requested: str) -> torch.device:
    if requested != "auto":
        return torch.device(requested)
    if torch.cuda.is_available():
        return torch.device("cuda")
    if hasattr(torch.backends, "mps") and torch.backends.mps.is_available():
        return torch.device("mps")
    return torch.device("cpu")


def dtype_from_name(name: str) -> torch.dtype:
    return {"float32": torch.float32, "bfloat16": torch.bfloat16, "float16": torch.float16}[name]


def lr_at(step: int, total: int, warmup: int, peak: float) -> float:
    if warmup > 0 and step < warmup:
        return peak * (step + 1) / warmup
    if total <= warmup:
        return peak
    ratio = min(1.0, max(0.0, (step - warmup) / (total - warmup)))
    return peak * (0.1 + 0.9 * 0.5 * (1.0 + math.cos(math.pi * ratio)))


@torch.no_grad()
def evaluate(model: TinyLM, data: Tensor, batch_size: int, context: int,
             batches: int, device: torch.device) -> float:
    model.eval()
    losses = []
    for _ in range(batches):
        x, y = sample_batch(data, batch_size, context, device)
        _, loss = model(x, y)
        losses.append(float(loss))
    model.train()
    return sum(losses) / len(losses)


def peak_memory_bytes(device: torch.device) -> Optional[int]:
    if device.type == "cuda":
        return int(torch.cuda.max_memory_allocated(device))
    return None


def reset_peak_memory(device: torch.device) -> None:
    if device.type == "cuda":
        torch.cuda.reset_peak_memory_stats(device)


def train(a: argparse.Namespace) -> None:
    random.seed(a.seed)
    torch.manual_seed(a.seed)
    if torch.cuda.is_available():
        torch.cuda.manual_seed_all(a.seed)

    device = choose_device(a.device)
    dtype = dtype_from_name(a.dtype)
    if device.type == "cpu" and dtype == torch.float16:
        print("WARNING: float16 on CPU is usually slow/unsupported; using float32 instead.")
        dtype = torch.float32

    cfg = ModelConfig(
        context=a.context,
        n_layers=a.layers,
        d_model=a.d_model,
        n_heads=a.heads,
        d_ff=a.d_ff,
        dropout=a.dropout,
        mode=a.mode,
        rank=a.rank,
        latent_dim=a.latent_dim,
        constructor_hidden=a.constructor_hidden,
        constructor_type_dim=a.constructor_type_dim,
        constructor_fourier_bands=a.constructor_fourier_bands,
    )
    if cfg.rank > min(cfg.d_model, cfg.d_ff):
        raise SystemExit("--rank must be <= min(d_model, d_ff)")

    data = load_bytes(a.data, a.smoke_test)
    train_data, val_data = split_data(data)
    if min(train_data.numel(), val_data.numel()) <= cfg.context + 1:
        raise SystemExit("Corpus/split is too small for requested --context")

    model = TinyLM(cfg).to(device=device, dtype=dtype)
    counts = count_parameters(model)
    model_bytes = state_dict_bytes(model)

    run_name = a.run_name or f"{a.mode}_L{a.layers}_D{a.d_model}_R{a.rank}_Z{a.latent_dim}_seed{a.seed}"
    run_dir = a.output_dir / run_name
    run_dir.mkdir(parents=True, exist_ok=True)

    print("=" * 88)
    print("LATENT TRANSFORMER v0")
    print("=" * 88)
    print(f"mode:          {a.mode}")
    print(f"device/dtype:  {device} / {dtype}")
    print(f"corpus bytes:  {data.numel():,} (train {train_data.numel():,}, val {val_data.numel():,})")
    print(f"parameters:    {counts['total']:,}")
    print(f"state bytes:   {model_bytes:,} ({human_bytes(model_bytes)})")
    print(f"breakdown:     {counts}")
    print(f"run dir:       {run_dir}")

    optimizer = torch.optim.AdamW(model.parameters(), lr=a.lr, weight_decay=a.weight_decay)
    reset_peak_memory(device)
    history = []
    tokens_seen = 0
    start = time.perf_counter()
    last_log = start
    last_log_tokens = 0

    for step in range(a.steps):
        lr = lr_at(step, a.steps, a.warmup_steps, a.lr)
        for group in optimizer.param_groups:
            group["lr"] = lr

        optimizer.zero_grad(set_to_none=True)
        total_loss = 0.0
        for _ in range(a.grad_accum):
            x, y = sample_batch(train_data, a.batch_size, cfg.context, device)
            _, loss = model(x, y)
            (loss / a.grad_accum).backward()
            total_loss += float(loss.detach())
            tokens_seen += x.numel()

        if a.grad_clip > 0:
            nn.utils.clip_grad_norm_(model.parameters(), a.grad_clip)
        optimizer.step()

        one_based = step + 1
        if one_based == 1 or one_based % a.log_every == 0:
            now = time.perf_counter()
            dt = max(1e-9, now - last_log)
            rate = (tokens_seen - last_log_tokens) / dt
            print(f"step {one_based:6d}/{a.steps} | train {total_loss/a.grad_accum:.4f} | "
                  f"lr {lr:.3g} | {rate:,.0f} tok/s")
            last_log, last_log_tokens = now, tokens_seen

        if one_based == 1 or one_based % a.eval_every == 0 or one_based == a.steps:
            val_loss = evaluate(model, val_data, a.batch_size, cfg.context,
                                a.eval_batches, device)
            elapsed = time.perf_counter() - start
            row = {
                "step": one_based,
                "tokens_seen": tokens_seen,
                "train_loss": total_loss / a.grad_accum,
                "val_loss": val_loss,
                "perplexity": math.exp(min(20.0, val_loss)),
                "elapsed_seconds": elapsed,
                "tokens_per_second_overall": tokens_seen / max(elapsed, 1e-9),
                "peak_device_memory_bytes": peak_memory_bytes(device),
            }
            history.append(row)
            print(f"  EVAL val {val_loss:.4f} | ppl {row['perplexity']:.2f} | "
                  f"overall {row['tokens_per_second_overall']:,.0f} tok/s")

    prompt = a.generate_prompt.encode("utf-8", errors="replace")
    prompt_ids = torch.tensor([list(prompt)], dtype=torch.long, device=device)
    generated = model.generate(prompt_ids, a.generate_tokens)[0].detach().cpu().tolist()
    sample_text = bytes(generated).decode("utf-8", errors="replace")

    checkpoint = {
        "model_config": asdict(cfg),
        "model_state": model.state_dict(),
        "training_args": vars(a) | {"data": str(a.data) if a.data else None,
                                    "output_dir": str(a.output_dir)},
        "history": history,
    }
    checkpoint_path = run_dir / "model.pt"
    torch.save(checkpoint, checkpoint_path)

    report = {
        "experiment": "latent_transformer_v0",
        "model_config": asdict(cfg),
        "mode": a.mode,
        "seed": a.seed,
        "device": str(device),
        "dtype": str(dtype),
        "corpus_bytes": int(data.numel()),
        "parameter_counts": counts,
        "state_dict_bytes_before_save": model_bytes,
        "checkpoint_file_bytes": checkpoint_path.stat().st_size,
        "optimizer_parameter_elements": sum(p.numel() for g in optimizer.param_groups for p in g["params"]),
        "history": history,
        "sample": sample_text,
    }
    (run_dir / "report.json").write_text(json.dumps(report, indent=2) + "\n")
    (run_dir / "sample.txt").write_text(sample_text, errors="replace")

    print("\n" + "=" * 88)
    print("DONE")
    print("=" * 88)
    print(f"checkpoint: {checkpoint_path} ({human_bytes(checkpoint_path.stat().st_size)})")
    print(f"report:     {run_dir / 'report.json'}")
    print("\nSAMPLE:\n" + sample_text)


def main() -> None:
    a = parse_args()
    if a.steps < 1:
        raise SystemExit("--steps must be >= 1")
    if a.batch_size < 1 or a.grad_accum < 1:
        raise SystemExit("batch size and grad accumulation must be >= 1")
    train(a)


if __name__ == "__main__":
    main()
"""E40 adaptive residual codec: real model coordination with local representations.

The codec is a predictive layer that can sit beside a base model/codec:
the Predictor supplies a deterministic prediction, E40 measures the residual,
chooses the cheapest complete representation for each region, and serializes
the choice plus the local structural signature needed to reproduce it.

Exact reconstruction is mandatory. No oracle or precomputed strategy map is
used during encoding.
"""
from __future__ import annotations

from dataclasses import dataclass
from typing import Callable, Protocol
import math
import struct
import zlib

MAGIC = b"NC40"
VERSION = 2
FILE_HEADER = struct.Struct("<4sBII")
REGION_HEADER = struct.Struct("<BII3B")


@dataclass(frozen=True)
class RegionSignature:
    """Quantized local behavior, independent of absolute position."""

    entropy_q: int
    repetition_q: int
    unique_q: int

    def pack(self) -> bytes:
        return bytes((self.entropy_q, self.repetition_q, self.unique_q))

    @classmethod
    def unpack(cls, data: bytes) -> "RegionSignature":
        if len(data) != 3:
            raise ValueError("invalid region signature")
        return cls(*data)


@dataclass(frozen=True)
class Representation:
    """A representation defines a maximum predictive capacity and coding mode."""

    name: str
    context_size: int
    mode: str
    compression_level: int


# These are genuinely different predictive representations.
REPRESENTATIONS = (
    Representation("compact", 1, "previous", 1),
    Representation("balanced", 2, "delta", 6),
    Representation("deep", 3, "second_order", 9),
    Representation("raw", 0, "zero", 6),
)


class Predictor(Protocol):
    """Pluggable model interface.

    predict() must be deterministic for the supplied model state and arguments.
    observe() is called once, after the winning representation is selected.
    This lets a stateful external model evolve identically at both ends without
    being updated by losing candidate evaluations.
    """

    def predict(
        self,
        context: bytes,
        length: int,
        position: int,
        representation: Representation,
        signature: RegionSignature,
    ) -> bytes:
        ...

    def observe(
        self,
        region: bytes,
        position: int,
        representation: Representation,
        signature: RegionSignature,
    ) -> None:
        ...


class ContextPredictor:
    """Small deterministic reference model for E40.

    The signature controls effective context capacity. This makes the local
    structural representation part of the actual prediction path while keeping
    the predictor simple enough that E40's mechanics remain visible.
    """

    def _effective_context(
        self, representation: Representation, signature: RegionSignature
    ) -> int:
        if representation.context_size == 0:
            return 0
        if signature.repetition_q >= 192:
            return 1
        if signature.entropy_q < 96 and signature.unique_q < 64:
            return min(2, representation.context_size)
        return representation.context_size

    def predict(self, context, length, position, representation, signature):
        effective_context = self._effective_context(representation, signature)
        history = bytearray(context[-effective_context:])
        output = bytearray()

        for _ in range(length):
            if representation.mode == "zero" or not history:
                value = 0
            elif representation.mode == "previous":
                value = history[-1]
            elif representation.mode == "delta":
                value = (
                    (2 * history[-1] - history[-2]) & 0xFF
                    if len(history) >= 2
                    else history[-1]
                )
            elif representation.mode == "second_order":
                value = (
                    (3 * history[-1] - 3 * history[-2] + history[-3]) & 0xFF
                    if len(history) >= 3
                    else history[-1]
                )
            else:
                raise ValueError(f"unknown representation mode: {representation.mode}")

            output.append(value)
            history.append(value)

        return bytes(output)

    def observe(self, region, position, representation, signature):
        return None


def analyze_region(data: bytes) -> RegionSignature:
    """Describe local behavior without using absolute location."""

    if not data:
        return RegionSignature(0, 255, 0)

    counts = [0] * 256
    for value in data:
        counts[value] += 1

    n = len(data)
    entropy = -sum(
        (count / n) * math.log2(count / n) for count in counts if count
    )
    repetition = sum(a == b for a, b in zip(data, data[1:])) / max(1, n - 1)
    unique_fraction = sum(count > 0 for count in counts) / 256

    return RegionSignature(
        round(entropy / 8 * 255),
        round(repetition * 255),
        round(unique_fraction * 255),
    )


def _xor(actual: bytes, predicted: bytes) -> bytes:
    if len(actual) != len(predicted):
        raise ValueError("prediction length does not match region length")
    return bytes(a ^ b for a, b in zip(actual, predicted))


def _predict(
    predictor: Predictor,
    previous: bytes,
    length: int,
    position: int,
    representation: Representation,
    signature: RegionSignature,
) -> bytes:
    predicted = predictor.predict(
        previous,
        length,
        position,
        representation,
        signature,
    )
    if len(predicted) != length:
        raise ValueError("predictor returned incorrect region length")
    return predicted


def candidate_cost(coded_length: int) -> int:
    """Complete encoded cost for one candidate, including region metadata."""
    return REGION_HEADER.size + coded_length


def _encode_region_candidates(
    region: bytes,
    previous: bytes,
    position: int,
    predictor: Predictor,
    signature: RegionSignature,
):
    candidates = []
    for rid, representation in enumerate(REPRESENTATIONS):
        prediction = _predict(
            predictor, previous, len(region), position, representation, signature
        )
        residual = _xor(region, prediction)
        coded = zlib.compress(residual, representation.compression_level)
        candidates.append(
            {
                "rid": rid,
                "representation": representation,
                "coded": coded,
                "residual_length": len(residual),
                "cost": candidate_cost(len(coded)),
            }
        )
    return candidates


@dataclass
class EncodeStats:
    input_bytes: int
    encoded_bytes: int
    region_count: int
    representation_counts: dict[str, int]
    adaptive_region_cost: int
    fixed_region_costs: dict[str, int]
    signatures: list[RegionSignature]

    @property
    def ratio(self) -> float:
        return self.encoded_bytes / max(1, self.input_bytes)

    @property
    def reduction_percent(self) -> float:
        if not self.input_bytes:
            return 0.0
        return (1.0 - self.encoded_bytes / self.input_bytes) * 100.0

    @property
    def fixed_total_costs(self) -> dict[str, int]:
        return {
            name: FILE_HEADER.size + cost
            for name, cost in self.fixed_region_costs.items()
        }


def _measure_fixed(
    data: bytes,
    region_size: int,
    predictor_factory: Callable[[], Predictor],
) -> dict[str, int]:
    """Measure true fixed-representation streams with independent model state."""

    totals = {representation.name: 0 for representation in REPRESENTATIONS}

    for _, representation in enumerate(REPRESENTATIONS):
        predictor = predictor_factory()
        previous = b""

        for position, start in enumerate(range(0, len(data), region_size)):
            region = data[start:start + region_size]
            signature = analyze_region(region)
            prediction = _predict(
                predictor, previous, len(region), position, representation, signature
            )
            residual = _xor(region, prediction)
            coded = zlib.compress(residual, representation.compression_level)
            totals[representation.name] += candidate_cost(len(coded))
            predictor.observe(region, position, representation, signature)
            previous = region

    return totals


def encode(
    data: bytes,
    predictor: Predictor | None = None,
    region_size: int = 1024,
    *,
    return_stats: bool = False,
    predictor_factory: Callable[[], Predictor] | None = None,
):
    """Encode with measured adaptive representation selection.

    If return_stats=True, fixed-strategy comparison is also produced. For a
    custom stateful predictor, pass predictor_factory so each fixed strategy
    gets independent model state. The built-in ContextPredictor is handled
    automatically.
    """

    if region_size <= 0:
        raise ValueError("region_size must be positive")

    predictor = predictor or ContextPredictor()
    region_count = (len(data) + region_size - 1) // region_size
    out = bytearray(FILE_HEADER.pack(MAGIC, VERSION, region_size, region_count))
    previous = b""

    counts = {representation.name: 0 for representation in REPRESENTATIONS}
    signatures: list[RegionSignature] = []
    adaptive_region_cost = 0

    for position, start in enumerate(range(0, len(data), region_size)):
        region = data[start:start + region_size]
        signature = analyze_region(region)
        signatures.append(signature)

        candidates = _encode_region_candidates(
            region, previous, position, predictor, signature
        )

        # No oracle: all real candidates are measured and the complete
        # end-to-end cost (metadata + payload) determines the winner.
        winner = min(
            candidates,
            key=lambda candidate: (candidate["cost"], candidate["rid"]),
        )
        representation = winner["representation"]

        out += REGION_HEADER.pack(
            winner["rid"],
            len(winner["coded"]),
            winner["residual_length"],
            *signature.pack(),
        )
        out += winner["coded"]

        counts[representation.name] += 1
        adaptive_region_cost += winner["cost"]

        # Update the shared/base model only with the actual selected path.
        predictor.observe(region, position, representation, signature)
        previous = region

    blob = bytes(out)

    if not return_stats:
        return blob

    if predictor_factory is None and isinstance(predictor, ContextPredictor):
        predictor_factory = ContextPredictor

    fixed_costs = (
        _measure_fixed(data, region_size, predictor_factory)
        if predictor_factory is not None
        else {}
    )

    return blob, EncodeStats(
        input_bytes=len(data),
        encoded_bytes=len(blob),
        region_count=region_count,
        representation_counts=counts,
        adaptive_region_cost=adaptive_region_cost,
        fixed_region_costs=fixed_costs,
        signatures=signatures,
    )


def decode(blob: bytes, predictor: Predictor | None = None) -> bytes:
    """Decode using only the serialized stream and synchronized predictor state."""

    predictor = predictor or ContextPredictor()

    if len(blob) < FILE_HEADER.size:
        raise ValueError("invalid NC40 stream")

    magic, version, region_size, count = FILE_HEADER.unpack_from(blob, 0)
    if magic != MAGIC:
        raise ValueError("invalid NC40 stream")
    if version != VERSION:
        raise ValueError("unsupported NC40 version")
    if region_size <= 0:
        raise ValueError("invalid region size")

    pointer = FILE_HEADER.size
    out = bytearray()
    previous = b""

    for position in range(count):
        if pointer + REGION_HEADER.size > len(blob):
            raise ValueError("truncated region header")

        rid, compressed_length, raw_length, entropy_q, repetition_q, unique_q = (
            REGION_HEADER.unpack_from(blob, pointer)
        )
        pointer += REGION_HEADER.size

        if rid >= len(REPRESENTATIONS):
            raise ValueError("invalid representation id")
        if raw_length <= 0 or raw_length > region_size:
            raise ValueError("invalid region raw length")
        if position < count - 1 and raw_length != region_size:
            raise ValueError("non-final region has incorrect length")
        if compressed_length > len(blob) - pointer:
            raise ValueError("truncated region payload")

        signature = RegionSignature(entropy_q, repetition_q, unique_q)
        coded = blob[pointer:pointer + compressed_length]
        pointer += compressed_length

        try:
            residual = zlib.decompress(coded)
        except zlib.error as exc:
            raise ValueError("invalid compressed residual") from exc

        if len(residual) != raw_length:
            raise ValueError("residual length mismatch")

        representation = REPRESENTATIONS[rid]
        prediction = _predict(
            predictor, previous, raw_length, position, representation, signature
        )
        region = _xor(residual, prediction)

        predictor.observe(region, position, representation, signature)
        out += region
        previous = region

    if pointer != len(blob):
        raise ValueError("trailing bytes")

    if count != 0 and len(out) == 0:
        raise ValueError("invalid empty stream")

    return bytes(out)


def roundtrip(data: bytes, predictor: Predictor | None = None, region_size: int = 1024):
    blob = encode(data, predictor, region_size)
    decoded = decode(blob, predictor)
    if decoded != data:
        raise AssertionError("exact reconstruction failed")
    return blob, len(blob) / max(1, len(data))


def _demo():
    """Run a mixed local-structure smoke corpus and report useful metrics."""

    repeated = b"neural compression: persistent structure. " * 300
    linear = bytes((i * 3 + 7) % 256 for i in range(4096))
    quadratic = bytes((i * i + 11) % 256 for i in range(4096))

    noisy = bytes(rng.randrange(256) for _ in range(4096))

    blob, stats = encode(data, region_size=512, return_stats=True)
    exact = decode(blob) == data

    print(f"encoded={stats.encoded_bytes}")
    print(f"ratio={stats.ratio:.4f}")

"""E41 — Relational Concept Memory.

Question
--------
Can a persistent representation organize around reusable relations between
observations rather than the arbitrary symbols through which observations
arrive, and can that memory aid a separate predictor under genuine ambiguity?

Design
------
A synthetic world contains evaluator-only concept identities, continuous
nonlinguistic features, arbitrary surface tokens, aliases, and typed relations.

The decisive comparison is deliberately strict:

    frozen BasePredictor
        current observation -> prediction

    MemoryAidedPredictor
        the same frozen BasePredictor
        + persistent relational state built from prior observations
        -> residual correction -> prediction

The memory-aided model therefore cannot win merely because it has a different
base encoder/head. With zero memory its output is exactly the frozen base
prediction.

Two language pathologies are built into the world:

* homonym pressure: different underlying concepts share the same primary token;
* alias/synonym pressure: the same underlying concept may arrive through two
  different tokens.

For the homonym probe the current nonlinguistic feature is masked to zero.
Thus same-token concepts present exactly the same local token/feature evidence
for a given relation type. Any disambiguation must come from persistent
relational context accumulated from prior observations of that concept.

Hidden concept ids are used only by the simulator/evaluator to choose which
observations belong to an episode. They are never supplied to either network.

The post-training remap probe permutes the vocabulary and retrains only the
token embedding table. All other representation, memory, and prediction
parameters remain frozen.
"""
from __future__ import annotations

from dataclasses import dataclass
import argparse
import copy
import json
import math
import random
from pathlib import Path

import numpy as np
import torch
from torch import nn
import torch.nn.functional as F


@dataclass(frozen=True)
class Config:
    seed: int = 41
    concepts: int = 48
    families: int = 8
    feature_dim: int = 12
    relation_types: int = 4
    token_count: int = 64
    latent_dim: int = 24
    memory_slots: int = 24
    epochs: int = 180
    episodes_per_epoch: int = 96
    lr: float = 2e-3
    remap_epochs: int = 45
    sparsity_weight: float = 2e-4


@dataclass
class World:
    # All indices into these tensors are simulator/evaluator-only concept ids.
    features: torch.Tensor
    family: torch.Tensor
    tokens: torch.Tensor
    aliases: torch.Tensor
    relations: list[tuple[int, int, int]]


def seed_all(seed: int) -> None:
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)


def make_world(cfg: Config) -> World:
    """Create a latent world whose symbol mapping is intentionally misleading."""
    if cfg.concepts % cfg.families != 0:
        raise ValueError("concepts must be divisible by families")
    if cfg.token_count <= cfg.concepts:
        raise ValueError("token_count must exceed concepts so aliases can be distinct")

    g = torch.Generator().manual_seed(cfg.seed)
    per_family = cfg.concepts // cfg.families
    family = torch.arange(cfg.concepts) // per_family

    centers = F.normalize(
        torch.randn(cfg.families, cfg.feature_dim, generator=g), dim=-1
    )
    features = centers[family] + 0.12 * torch.randn(
        cfg.concepts, cfg.feature_dim, generator=g
    )
    features = F.normalize(features, dim=-1)

    # Start with one unique primary symbol per concept.
    tokens = torch.arange(cfg.concepts, dtype=torch.long)

    # Homonyms: concepts from distant families share a primary surface symbol.
    for i in range(min(6, cfg.families)):
        a = i * per_family
        b = ((i + cfg.families // 2) % cfg.families) * per_family
        if a != b:
            tokens[b] = tokens[a]

    # Aliases: the *same* underlying concept can arrive with a different token.
    # -1 means that concept has no alias.
    aliases = torch.full((cfg.concepts,), -1, dtype=torch.long)
    alias_pool = list(range(cfg.concepts, cfg.token_count))
    for n, concept in enumerate(range(min(len(alias_pool), cfg.concepts))):
        aliases[concept] = alias_pool[n]

    # Relations are generated from hidden structure. Two relation types are
    # mostly within-family, while the others are unconstrained.
    relations: list[tuple[int, int, int]] = []
    rng = np.random.default_rng(cfg.seed)
    for src in range(cfg.concepts):
        same = torch.where(family == family[src])[0].tolist()
        same = [x for x in same if x != src]
        for rel_type in range(cfg.relation_types):
            if rel_type < 2 and same:
                dst = int(rng.choice(same))
            else:
                dst = int(rng.integers(cfg.concepts))
                while dst == src:
                    dst = int(rng.integers(cfg.concepts))
            relations.append((src, rel_type, dst))

    return World(features, family, tokens, aliases, relations)


def token_choices(world: World, concept: int) -> tuple[int, ...]:
    primary = int(world.tokens[concept])
    alias = int(world.aliases[concept])
    return (primary,) if alias < 0 else (primary, alias)


def sample_token(world: World, concept: int) -> int:
    return random.choice(token_choices(world, concept))


def ambiguous_primary_tokens(world: World) -> set[int]:
    groups: dict[int, set[int]] = {}
    for i, token in enumerate(world.tokens.tolist()):
        groups.setdefault(int(token), set()).add(int(world.family[i]))
    return {token for token, families in groups.items() if len(families) > 1}


def is_ambiguous_concept(world: World, concept: int) -> bool:
    return int(world.tokens[concept]) in ambiguous_primary_tokens(world)


def split_relations(world: World, seed: int):
    rng = random.Random(seed)
    rels = world.relations[:]
    rng.shuffle(rels)
    cut = int(0.75 * len(rels))
    return rels[:cut], rels[cut:]


def relations_by_source(rels: list[tuple[int, int, int]]):
    grouped: dict[int, list[tuple[int, int, int]]] = {}
    for rel in rels:
        grouped.setdefault(rel[0], []).append(rel)
    return grouped


def noisy_feature(world: World, idx: int, scale: float = 0.08):
    return F.normalize(
        world.features[idx] + scale * torch.randn_like(world.features[idx]), dim=-1
    )


def query_feature(world: World, idx: int, masked: bool):
    """Current local nonlinguistic evidence.

    For the decisive ambiguity probe this is exactly zero, so two concepts that
    share a token are locally indistinguishable for the same relation type.
    """
    if masked:
        return torch.zeros_like(world.features[idx])
    return noisy_feature(world, idx)


def one(x: int):
    return torch.tensor(x, dtype=torch.long)


class ObservationEncoder(nn.Module):
    def __init__(self, cfg: Config):
        super().__init__()
        self.token = nn.Embedding(cfg.token_count, cfg.latent_dim)
        self.feature = nn.Sequential(
            nn.Linear(cfg.feature_dim, cfg.latent_dim),
            nn.GELU(),
            nn.Linear(cfg.latent_dim, cfg.latent_dim),
        )
        self.relation = nn.Embedding(cfg.relation_types, cfg.latent_dim)
        self.mix = nn.Sequential(
            nn.Linear(cfg.latent_dim * 3, cfg.latent_dim),
            nn.GELU(),
            nn.LayerNorm(cfg.latent_dim),
        )

    def forward(self, token, feature, relation_type):
        return self.mix(
            torch.cat(
                [
                    self.token(token),
                    self.feature(feature),
                    self.relation(relation_type),
                ],
                dim=-1,
            )
        )


class BasePredictor(nn.Module):
    def __init__(self, cfg: Config):
        super().__init__()
        self.encoder = ObservationEncoder(cfg)
        self.head = nn.Linear(cfg.latent_dim, cfg.feature_dim)

    def forward(self, token, feature, relation_type):
        z = self.encoder(token, feature, relation_type)
        return F.normalize(self.head(z), dim=-1), z


class PersistentRelationalMemory(nn.Module):
    """Content-addressed slots with no concept-specific addresses."""

    def __init__(self, cfg: Config):
        super().__init__()
        self.cfg = cfg
        self.keys = nn.Parameter(
            torch.randn(cfg.memory_slots, cfg.latent_dim) / math.sqrt(cfg.latent_dim)
        )
        self.message = nn.Sequential(
            nn.Linear(cfg.latent_dim * 2, cfg.latent_dim),
            nn.GELU(),
            nn.Linear(cfg.latent_dim, cfg.latent_dim),
        )
        self.gate = nn.Linear(cfg.latent_dim * 2, 1)

    def empty(self, device=None):
        return torch.zeros(
            self.cfg.memory_slots, self.cfg.latent_dim, device=device
        )

    def read(self, state, query):
        logits = (query @ (self.keys + state).T) / math.sqrt(self.cfg.latent_dim)
        weights = logits.softmax(-1)
        return weights @ state, weights

    def write(self, state, evidence, related):
        query = evidence + related
        logits = (query @ (self.keys + state).T) / math.sqrt(self.cfg.latent_dim)
        weights = logits.softmax(-1)
        msg = self.message(torch.cat([evidence, related], -1))
        proposal = state + weights[:, None] * msg[None, :]
        gate = torch.sigmoid(self.gate(torch.cat([state, proposal], -1)))
        return gate * proposal + (1.0 - gate) * state


class MemoryAidedPredictor(nn.Module):
    """Frozen base predictor plus a learned persistent-memory residual.

    Because the correction is multiplied by ||recalled||, an empty memory
    produces exactly the frozen base prediction even after memory training.
    """

    def __init__(self, cfg: Config, base: BasePredictor):
        super().__init__()
        self.cfg = cfg
        self.base = copy.deepcopy(base)
        for p in self.base.parameters():
            p.requires_grad = False

        self.memory = PersistentRelationalMemory(cfg)
        self.aid = nn.Sequential(
            nn.Linear(cfg.latent_dim * 2, cfg.latent_dim),
            nn.GELU(),
            nn.Linear(cfg.latent_dim, cfg.feature_dim, bias=False),
        )

    def predict(self, state, token, feature, relation_type):
        base_pred, z = self.base(token, feature, relation_type)
        recalled, weights = self.memory.read(state, z)
        correction = self.aid(torch.cat([z, recalled], -1))
        # Exact base behavior when recalled == 0.
        scale = recalled.norm().clamp(max=1.0)
        out = F.normalize(base_pred + scale * correction, dim=-1)
        return out, base_pred, z, recalled, weights

    def write_observation(
        self,
        state,
        token: int,
        source_feature: torch.Tensor,
        relation_type: int,
        related_feature: torch.Tensor,
    ):
        # The encoder is frozen, so the memory has to learn how to organize
        # evidence instead of changing the underlying base representation.
        with torch.no_grad():
            z = self.base.encoder(one(token), source_feature, one(relation_type))
            related = self.base.encoder.feature(related_feature)
        return self.memory.write(state, z, related)


def train_base(model, world, train_rel, cfg):
    """Train the common base predictor before any memory is added."""
    opt = torch.optim.AdamW(model.parameters(), lr=cfg.lr)
    model.train()
    ambiguous = ambiguous_primary_tokens(world)

    for _ in range(cfg.epochs):
        random.shuffle(train_rel)
        for src, r, dst in train_rel[: cfg.episodes_per_epoch]:
            # The base sees the same difficult masked-query distribution used
            # later by the memory system, not just easy full-feature examples.
            primary = int(world.tokens[src])
            masked = primary in ambiguous and random.random() < 0.5
            token = primary if masked else sample_token(world, src)
            pred, _ = model(
                one(token), query_feature(world, src, masked), one(r)
            )
            loss = 1.0 - F.cosine_similarity(
                pred[None], world.features[dst][None]
            ).mean()
            opt.zero_grad()
            loss.backward()
            opt.step()


def build_context_state(
    model: MemoryAidedPredictor,
    world: World,
    context_relations: list[tuple[int, int, int]],
    context_fraction: float = 1.0,
    differentiable: bool = False,
):
    """Build state from prior observations without exposing concept ids to model.

    The evaluator chooses episode membership using hidden ids. The network only
    receives the resulting token/feature/relation observations.
    """
    state = model.memory.empty()
    keep = int(round(len(context_relations) * context_fraction))
    if context_fraction > 0.0 and context_relations:
        keep = max(1, keep)
    selected = context_relations[:keep]

    for src, r, dst in selected:
        token = sample_token(world, src)
        source_feature = noisy_feature(world, src)
        related_feature = noisy_feature(world, dst)
        state = model.write_observation(
            state, token, source_feature, r, related_feature
        )
        if not differentiable:
            state = state.detach()
    return state


def train_memory(model, world, train_rel, cfg):
    """Train memory on multi-observation episodes.

    The query loss backpropagates through all writes that built its context
    state. This fixes the earlier one-step detach bug: the writer is now
    directly rewarded when a stored relation helps a later prediction.
    """
    trainable = [p for p in model.parameters() if p.requires_grad]
    opt = torch.optim.AdamW(trainable, lr=cfg.lr)
    grouped = relations_by_source(train_rel)
    sources = [src for src, rels in grouped.items() if len(rels) >= 2]

    model.train()
    for _ in range(cfg.epochs):
        random.shuffle(sources)
        used = 0
        for src in sources:
            rels = grouped[src][:]
            random.shuffle(rels)
            query_rel = rels[0]
            context = rels[1:]
            if not context:
                continue

            # Do not detach while constructing the episode. The later query
            # loss must train the earlier writes.
            state = build_context_state(
                model, world, context, context_fraction=1.0, differentiable=True
            )

            q_src, q_r, q_dst = query_rel
            masked = is_ambiguous_concept(world, q_src)
            token = int(world.tokens[q_src]) if masked else sample_token(world, q_src)
            pred, _, _, _, _ = model.predict(
                state,
                one(token),
                query_feature(world, q_src, masked),
                one(q_r),
            )
            pred_loss = 1.0 - F.cosine_similarity(
                pred[None], world.features[q_dst][None]
            ).mean()
            loss = pred_loss + cfg.sparsity_weight * state.abs().mean()

            opt.zero_grad()
            loss.backward()
            opt.step()

            used += 1
            if used >= cfg.episodes_per_epoch:
                break


def evaluate_base(model, world, rels, masked_ambiguity: bool = False):
    model.eval()
    scores = []
    ambiguous = ambiguous_primary_tokens(world)
    with torch.no_grad():
        for src, r, dst in rels:
            primary = int(world.tokens[src])
            masked = masked_ambiguity and primary in ambiguous
            pred, _ = model(
                one(primary),
                torch.zeros_like(world.features[src]) if masked else world.features[src],
                one(r),
            )
            scores.append(
                float(F.cosine_similarity(pred[None], world.features[dst][None]))
            )
    return float(np.mean(scores)) if scores else float("nan")


def evaluate_memory(
    model,
    world,
    train_rel,
    test_rel,
    context_fraction: float = 1.0,
    masked_ambiguity: bool = False,
    ambiguous_only: bool = False,
):
    model.eval()
    grouped = relations_by_source(train_rel)
    ambiguous = ambiguous_primary_tokens(world)
    scores = []

    with torch.no_grad():
        for src, r, dst in test_rel:
            primary = int(world.tokens[src])
            is_amb = primary in ambiguous
            if ambiguous_only and not is_amb:
                continue

            state = build_context_state(
                model,
                world,
                grouped.get(src, []),
                context_fraction=context_fraction,
            )
            masked = masked_ambiguity and is_amb
            pred, _, _, _, _ = model.predict(
                state,
                one(primary),
                torch.zeros_like(world.features[src]) if masked else world.features[src],
                one(r),
            )
            scores.append(
                float(F.cosine_similarity(pred[None], world.features[dst][None]))
            )
    return float(np.mean(scores)) if scores else float("nan")


def evaluate_base_ambiguous_only(model, world, rels):
    ambiguous = ambiguous_primary_tokens(world)
    subset = [rel for rel in rels if int(world.tokens[rel[0]]) in ambiguous]
    return evaluate_base(model, world, subset, masked_ambiguity=True)


def homonym_memory_separation(model, world, train_rel):
    """Compare persistent states for same-token/different-family concepts."""
    grouped = relations_by_source(train_rel)
    by_token: dict[int, list[int]] = {}
    for concept, token in enumerate(world.tokens.tolist()):
        by_token.setdefault(int(token), []).append(concept)

    vals = []
    model.eval()
    with torch.no_grad():
        for ids in by_token.values():
            for i, a in enumerate(ids):
                for b in ids[i + 1 :]:
                    if int(world.family[a]) == int(world.family[b]):
                        continue
                    if not grouped.get(a) or not grouped.get(b):
                        continue
                    sa = build_context_state(model, world, grouped[a])
                    sb = build_context_state(model, world, grouped[b])
                    vals.append(
                        float(
                            F.cosine_similarity(
                                sa.flatten()[None], sb.flatten()[None]
                            )
                        )
                    )
    return float(np.mean(vals)) if vals else float("nan")


def alias_boundary_consistency(model, world, train_rel):
    """Same underlying concept, two different surface tokens."""
    grouped = relations_by_source(train_rel)
    pred_cos = []
    read_cos = []

    model.eval()
    with torch.no_grad():
        for src in range(len(world.tokens)):
            alias = int(world.aliases[src])
            if alias < 0 or not grouped.get(src):
                continue
            context = grouped[src]
            state = build_context_state(model, world, context)
            _, r, _ = context[0]

            p1, _, _, _, w1 = model.predict(
                state, one(int(world.tokens[src])), world.features[src], one(r)
            )
            p2, _, _, _, w2 = model.predict(
                state, one(alias), world.features[src], one(r)
            )
            pred_cos.append(float(F.cosine_similarity(p1[None], p2[None])))
            read_cos.append(float(F.cosine_similarity(w1[None], w2[None])))

    return {
        "prediction_cosine": float(np.mean(pred_cos)) if pred_cos else float("nan"),
        "read_weight_cosine": float(np.mean(read_cos)) if read_cos else float("nan"),
    }


def remap_world(world: World, permutation: torch.Tensor) -> World:
    aliases = world.aliases.clone()
    valid = aliases >= 0
    aliases[valid] = permutation[aliases[valid]]
    return World(
        features=world.features,
        family=world.family,
        tokens=permutation[world.tokens],
        aliases=aliases,
        relations=world.relations,
    )


def boundary_remap_probe(model, world, train_rel, test_rel, cfg):
    """Permute vocabulary and relearn only the token embedding boundary."""
    g = torch.Generator().manual_seed(cfg.seed + 1000)
    permutation = torch.randperm(cfg.token_count, generator=g)
    remapped_world = remap_world(world, permutation)

    probe = copy.deepcopy(model)
    for p in probe.parameters():
        p.requires_grad = False

    token_weight = probe.base.encoder.token.weight
    with torch.no_grad():
        token_weight.normal_(mean=0.0, std=1.0 / math.sqrt(cfg.latent_dim))
    token_weight.requires_grad = True

    before = evaluate_memory(
        probe,
        remapped_world,
        train_rel,
        test_rel,
        context_fraction=1.0,
        masked_ambiguity=True,
        ambiguous_only=True,
    )

    opt = torch.optim.AdamW([token_weight], lr=cfg.lr)
    grouped = relations_by_source(train_rel)
    sources = [src for src, rels in grouped.items() if len(rels) >= 2]

    probe.train()
    for _ in range(cfg.remap_epochs):
        random.shuffle(sources)
        used = 0
        for src in sources:
            rels = grouped[src][:]
            random.shuffle(rels)
            query_rel = rels[0]
            context = rels[1:]
            state = build_context_state(
                probe,
                remapped_world,
                context,
                context_fraction=1.0,
                differentiable=True,
            )
            q_src, q_r, q_dst = query_rel
            masked = is_ambiguous_concept(remapped_world, q_src)
            token = (
                int(remapped_world.tokens[q_src])
                if masked
                else sample_token(remapped_world, q_src)
            )
            pred, _, _, _, _ = probe.predict(
                state,
                one(token),
                query_feature(remapped_world, q_src, masked),
                one(q_r),
            )
            loss = 1.0 - F.cosine_similarity(
                pred[None], remapped_world.features[q_dst][None]
            ).mean()
            opt.zero_grad()
            loss.backward()
            opt.step()

            used += 1
            if used >= cfg.episodes_per_epoch:
                break

    after = evaluate_memory(
        probe,
        remapped_world,
        train_rel,
        test_rel,
        context_fraction=1.0,
        masked_ambiguity=True,
        ambiguous_only=True,
    )
    return {
        "before_boundary_relearn_cosine": before,
        "after_boundary_relearn_cosine": after,
        "trainable_parameters": int(token_weight.numel()),
        "frozen_parameters": int(
            sum(p.numel() for p in probe.parameters()) - token_weight.numel()
        ),
    }


def run(cfg: Config):
    seed_all(cfg.seed)
    world = make_world(cfg)
    train_rel, test_rel = split_relations(world, cfg.seed)

    base = BasePredictor(cfg)
    train_base(base, world, train_rel, cfg)

    memory = MemoryAidedPredictor(cfg, base)
    train_memory(memory, world, train_rel, cfg)

    # Context-removal curve on the decisive same-token + masked-feature cases.
    context_curve = {}
    for fraction in (0.0, 0.1, 0.25, 0.5, 0.75, 1.0):
        context_curve[str(fraction)] = evaluate_memory(
            memory,
            world,
            train_rel,
            test_rel,
            context_fraction=fraction,
            masked_ambiguity=True,
            ambiguous_only=True,
        )

    result = {
        "experiment": "E41 — Relational Concept Memory",
        "seed": cfg.seed,
        "question": (
            "Can persistent relational context aid a frozen predictor when "
            "surface symbols and current local evidence are insufficient?"
        ),
        "full_feature_control": {
            "base_test_cosine": evaluate_base(base, world, test_rel),
            "memory_test_cosine": evaluate_memory(
                memory, world, train_rel, test_rel, context_fraction=1.0
            ),
            "memory_zero_context_cosine": evaluate_memory(
                memory, world, train_rel, test_rel, context_fraction=0.0
            ),
        },
        "genuine_ambiguity_probe": {
            "base_masked_homonym_cosine": evaluate_base_ambiguous_only(
                base, world, test_rel
            ),
            "memory_masked_homonym_cosine": context_curve["1.0"],
            "context_curve": context_curve,
        },
        "persistent_state_homonym_cosine": homonym_memory_separation(
            memory, world, train_rel
        ),
        "same_concept_alias_probe": alias_boundary_consistency(
            memory, world, train_rel
        ),
        "token_remap_boundary_probe": boundary_remap_probe(
            memory, world, train_rel, test_rel, cfg
        ),
        "persistent_scalar_slots": cfg.memory_slots * cfg.latent_dim,
        "train_relations": len(train_rel),
        "test_relations": len(test_rel),
        "ambiguous_primary_tokens": len(ambiguous_primary_tokens(world)),
        "aliased_concepts": int((world.aliases >= 0).sum()),
        "notes": [
            "Hidden concept ids are simulator/evaluator-only episode selectors.",
            "The memory-aided model contains an exact frozen copy of the trained base predictor.",
            "With empty memory, the residual correction is mathematically zero.",
            "Ambiguous homonym queries use the same token and a zero feature vector; relational context is the only concept-specific evidence available.",
            "Memory query loss backpropagates through the prior writes that built the episode state.",
            "Aliases give the same underlying concept two different surface labels.",
            "The vocabulary-remap probe retrains only the token embedding table while freezing the rest of the learned representation and memory system.",
            "Persistent-state cost is still reported in scalar slots; exact bit/entropy cost remains a separate compression measurement.",
        ],
    }

"""Command-line interface for the E40 adaptive residual codec."""
from __future__ import annotations

import argparse
from pathlib import Path

from E40_adaptive_residual_codec import decode, encode


def _print_stats(stats) -> None:
    print(f"input={stats.input_bytes}")
    print(f"encoded={stats.encoded_bytes}")
    print(f"ratio={stats.ratio:.4f}")
    print(f"reduction={stats.reduction_percent:.2f}%")
    print(f"regions={stats.region_count}")
    print("selected=" + ", ".join(
        f"{name}:{count}" for name, count in stats.representation_counts.items()
    ))
    if stats.fixed_total_costs:
        print("fixed_total=" + ", ".join(
            f"{name}:{cost}" for name, cost in stats.fixed_total_costs.items()
        ))
        best_fixed = min(stats.fixed_total_costs.values())
        print(f"best_fixed={best_fixed}")
        print(f"adaptive_vs_best_fixed={stats.encoded_bytes - best_fixed}")


def _build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(
        description="E40 exact adaptive residual codec"
    )
    subparsers = parser.add_subparsers(dest="command", required=True)

    encode_parser = subparsers.add_parser(
        "encode", help="encode a file into an NC40 stream"
    )
    encode_parser.add_argument("input", type=Path, help="input file")
    encode_parser.add_argument("output", type=Path, help="output NC40 file")
    encode_parser.add_argument(
        "--region-size", type=int, default=1024,
        help="bytes per region (default: 1024)",
    )
    encode_parser.add_argument(
        "--no-stats", action="store_true",
        help="skip fixed-strategy comparison",
    )

    decode_parser = subparsers.add_parser(
        "decode", help="decode an NC40 stream back to its original file"
    )
    decode_parser.add_argument("input", type=Path, help="input NC40 file")
    decode_parser.add_argument("output", type=Path, help="restored output file")
    return parser


def main() -> int:
    args = _build_parser().parse_args()

    if args.command == "encode":
        data = args.input.read_bytes()
        if args.no_stats:
            blob = encode(data, region_size=args.region_size)
            stats = None
        else:
            blob, stats = encode(
                data, region_size=args.region_size, return_stats=True
            )
        args.output.write_bytes(blob)
        print(f"encoded_file={args.output}")
        if stats is not None:
            _print_stats(stats)
        return 0

    data = decode(args.input.read_bytes())
    args.output.write_bytes(data)
    print(f"decoded_file={args.output}")
    print(f"output_bytes={len(data)}")
    return 0

#!/usr/bin/env python3
"""
E36 v4b — Local relational memory / double traversal (sparse)

Purpose
-------
Test whether a moving observer can build a reusable representation from
only locally available information and movement, without giving memory
absolute world coordinates or hidden world identifiers.

The simulator itself still uses world coordinates to perform visibility.
That is allowed. The information boundary is at the observer -> memory
interface.

Memory receives ONLY:
    - relative position of a visible feature to the observer
    - local feature vector
    - distance (derived locally from relative position)
    - observer movement delta
    - observer rotation delta
    - timestep as ordering, not as a spatial/world coordinate

Memory never receives:
    - world coordinates
    - world_index
    - the complete world
    - hidden geometry
    - position-derived feature vectors

Two identical traversals are run through the same world. Memory persists
between passes. The key measurement is whether pass 2 reuses the relational
structure built during pass 1 and therefore requires less expansion.

Relations are deliberately sparse: each observation connects only to
a small number of persistent local anchors and to its own previous
state. This prevents the representation from degenerating into an
all-pairs observation history.
"""

from __future__ import annotations

import json
import math
from dataclasses import dataclass, field
from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np


# ============================================================
# World
# ============================================================

@dataclass
class Voxel:
    pos: np.ndarray
    feature: np.ndarray


@dataclass
class World:
    voxels: list[Voxel]


def make_world(seed: int = 36) -> World:
    rng = np.random.default_rng(seed)
    voxels = []

    structures = [
        (np.array([0.0, 0.0, 0.0]), 2.5, 90),
        (np.array([7.0, 1.5, 2.0]), 2.0, 70),
        (np.array([2.0, 7.0, 3.5]), 2.2, 80),
        (np.array([8.0, 7.0, 1.0]), 1.6, 60),
    ]

    # IMPORTANT: feature is now an intrinsic local signature.
    # It is sampled independently of world position. The observer can
    # use it to recognize a previously encountered feature, but cannot
    # invert it to recover x/y/z.
    for center, radius, count in structures:
        for _ in range(count):
            d = rng.normal(size=3)
            d /= np.linalg.norm(d)
            r = radius * (rng.random() ** (1.0 / 3.0))
            pos = center + d * r

            # Stable intrinsic appearance/signature.
            feature = rng.normal(0.0, 1.0, size=4)
            feature /= np.linalg.norm(feature)
            feature += rng.normal(0.0, 0.012, size=4)

            voxels.append(Voxel(pos.astype(float), feature.astype(float)))

    return World(voxels)


# ============================================================
# Observer / visibility
# ============================================================

@dataclass
class Observer:
    position: np.ndarray
    direction: np.ndarray
    fov_degrees: float = 75.0
    max_range: float = 7.0


def normalize(v):
    n = np.linalg.norm(v)
    return v / n if n > 1e-12 else v


def rotation_delta(prev_direction, current_direction):
    if prev_direction is None:
        return np.zeros(3)

    a = normalize(prev_direction)
    b = normalize(current_direction)

    # A compact local rotation descriptor: cross product.
    # It carries relative orientation change, not world orientation.
    return np.cross(a, b)


def line_of_sight(origin, target, world: World, ignore_index: int):
    ray = target - origin
    distance = np.linalg.norm(ray)
    if distance < 1e-9:
        return True

    ray = ray / distance

    for i, voxel in enumerate(world.voxels):
        if i == ignore_index:
            continue

        rel = voxel.pos - origin
        along = np.dot(rel, ray)

        if along <= 0.0 or along >= distance:
            continue

        closest = origin + ray * along
        lateral = np.linalg.norm(voxel.pos - closest)
        blocker_radius = 0.20 + 0.015 * along

        if lateral < blocker_radius:
            return False

    return True


def observe(observer: Observer, world: World):
    visible = []

    forward = normalize(observer.direction)
    cos_half_fov = math.cos(math.radians(observer.fov_degrees / 2))

    for i, voxel in enumerate(world.voxels):
        rel = voxel.pos - observer.position
        distance = np.linalg.norm(rel)

        if distance < 1e-9 or distance > observer.max_range:
            continue

        direction = rel / distance
        if np.dot(direction, forward) < cos_half_fov:
            continue

        if line_of_sight(observer.position, voxel.pos, world, i):
            # Evaluator metadata is intentionally separate from what the
            # memory receives. This lets us measure coverage without leaking
            # an object/world ID into the representation.
            visible.append({
                "world_index": i,
                "relative_position": rel.copy(),
                "feature": voxel.feature.copy(),
                "distance": float(distance),
            })

    return visible


def memory_observations(visible):
    """Strip evaluator/world metadata before crossing the memory boundary."""
    return [
        {
            "relative_position": item["relative_position"].copy(),
            "feature": item["feature"].copy(),
            "distance": item["distance"],
        }
        for item in visible
    ]


# ============================================================
# Relational memory
# ============================================================

@dataclass
class Landmark:
    landmark_id: int
    feature: np.ndarray
    feature_m2: float = 0.0
    observations: int = 0
    first_seen: int = -1
    last_seen: int = -1
    passes_seen: set[int] = field(default_factory=set)


@dataclass
class Relation:
    from_landmark: int
    to_landmark: int
    # Relative motion accumulated between observations.
    motion_sum: np.ndarray
    motion_count: int
    # Relative landmark movement in observer coordinates.
    relative_shift_sum: np.ndarray
    relation_count: int
    first_pass: int
    last_pass: int


class RelationalMemory:
    """
    Local relational memory.

    A landmark is identified by intrinsic perceptual state, not position.
    Relations record how observations connect through the observer's
    movement. No absolute location is stored.
    """

    def __init__(self, feature_gate=0.22, new_landmark_gate=0.42):
        self.feature_gate = feature_gate
        self.new_landmark_gate = new_landmark_gate

        self.landmarks: list[Landmark] = []
        self.relations: dict[tuple[int, int], Relation] = {}
        self.next_landmark_id = 0

        self.previous_visible: list[tuple[int, np.ndarray]] = []
        self.previous_motion = np.zeros(3)
        self.previous_rotation = np.zeros(3)
        self.events = []

    def _match_landmark(self, feature):
        if not self.landmarks:
            return None, float("inf")

        best = None
        best_distance = float("inf")
        for landmark in self.landmarks:
            d = np.linalg.norm(feature - landmark.feature)
            if d < best_distance:
                best_distance = d
                best = landmark

        if best_distance <= self.feature_gate:
            return best, best_distance
        return None, best_distance

    def _create_landmark(self, feature, timestep, pass_id):
        landmark = Landmark(
            landmark_id=self.next_landmark_id,
            feature=feature.copy(),
            observations=1,
            first_seen=timestep,
            last_seen=timestep,
            passes_seen={pass_id},
        )
        self.next_landmark_id += 1
        self.landmarks.append(landmark)
        return landmark

    def _update_landmark(self, landmark, feature, timestep, pass_id):
        n = landmark.observations
        delta = feature - landmark.feature
        n_new = n + 1
        landmark.feature_m2 += np.dot(delta, delta) * n / n_new
        landmark.feature = landmark.feature + delta / n_new
        landmark.observations = n_new
        landmark.last_seen = timestep
        landmark.passes_seen.add(pass_id)

    def update(self, observations, timestep, pass_id, motion_delta, rotation_delta):
        matched = 0
        created = 0
        expanded = 0
        reused = 0
        relation_updates = 0

        current_visible = []

        for obs in observations:
            landmark, feature_distance = self._match_landmark(obs["feature"])

            if landmark is None:
                landmark = self._create_landmark(
                    obs["feature"], timestep, pass_id
                )
                created += 1
                expanded += 1
            else:
                was_seen_in_pass = pass_id in landmark.passes_seen
                self._update_landmark(
                    landmark,
                    obs["feature"],
                    timestep,
                    pass_id,
                )
                matched += 1
                if not was_seen_in_pass:
                    reused += 1

            current_visible.append(
                (landmark.landmark_id, obs["relative_position"].copy())
            )

        # Build a SPARSE relational topology.
        #
        # We do not store every co-visible pair. That would turn a local
        # state into a quadratic observation history. Instead:
        #   1. retain short temporal edges for landmarks that persist across
        #      consecutive viewpoints;
        #   2. retain at most a few nearest cross-landmark anchors per view.
        #
        # This is much closer to the user's "six degrees" intuition:
        # the system can trace a route through a small relational graph
        # instead of remembering every pair it ever saw.
        if self.previous_visible:
            previous_by_id = {lid: rel for lid, rel in self.previous_visible}
            for curr_id, curr_rel in current_visible:
                if curr_id not in previous_by_id:
                    continue

                prev_rel = previous_by_id[curr_id]
                key = (curr_id, curr_id)
                relation = self.relations.get(key)
                if relation is None:
                    relation = Relation(
                        from_landmark=curr_id,
                        to_landmark=curr_id,
                        motion_sum=np.zeros(3),
                        motion_count=0,
                        relative_shift_sum=np.zeros(3),
                        relation_count=0,
                        first_pass=pass_id,
                        last_pass=pass_id,
                    )
                    self.relations[key] = relation

                relation.motion_sum += motion_delta
                relation.motion_count += 1
                relation.relative_shift_sum += curr_rel - prev_rel
                relation.relation_count += 1
                relation.last_pass = pass_id
                relation_updates += 1

        # Sparse spatial anchors: for each current landmark, connect it to
        # up to two nearest OTHER landmarks visible at this viewpoint.
        # Relative positions only; no absolute world coordinate is stored.
        max_anchors = 2
        for i in range(len(current_visible)):
            a_id, a_rel = current_visible[i]
            candidates = []
            for j in range(len(current_visible)):
                if i == j:
                    continue
                b_id, b_rel = current_visible[j]
                d = np.linalg.norm(b_rel - a_rel)
                candidates.append((d, b_id, b_rel))

            candidates.sort(key=lambda x: x[0])
            for _, b_id, b_rel in candidates[:max_anchors]:
                key = (a_id, b_id)
                relation = self.relations.get(key)
                if relation is None:
                    relation = Relation(
                        from_landmark=a_id,
                        to_landmark=b_id,
                        motion_sum=np.zeros(3),
                        motion_count=0,
                        relative_shift_sum=np.zeros(3),
                        relation_count=0,
                        first_pass=pass_id,
                        last_pass=pass_id,
                    )
                    self.relations[key] = relation

                relation.relative_shift_sum += b_rel - a_rel
                relation.relation_count += 1
                relation.last_pass = pass_id
                relation_updates += 1

        self.previous_visible = current_visible
        self.previous_motion = motion_delta.copy()
        self.previous_rotation = rotation_delta.copy()

        self.events.append({
            "timestep": timestep,
            "pass": pass_id,
            "visible": len(observations),
            "landmarks": len(self.landmarks),
            "relations": len(self.relations),
            "created": created,
            "matched": matched,
            "reused": reused,
            "expanded": expanded,
            "relation_updates": relation_updates,
        })

    def begin_pass(self):
        # We retain knowledge, but reset only the short-term traversal state.
        self.previous_visible = []
        self.previous_motion = np.zeros(3)
        self.previous_rotation = np.zeros(3)

    def cost_slots(self):
        # Landmark: intrinsic feature (4), confidence/spread (1), count (1),
        # temporal metadata (2) = 8.
        landmark_cost = len(self.landmarks) * 8

        # Relation: relative motion (3), relative shift (3), count (1),
        # endpoints (2) = 9.
        relation_cost = len(self.relations) * 9
        return landmark_cost + relation_cost

    @staticmethod
    def raw_cost(observation_count):
        # relative position 3 + feature 4
        return observation_count * 7

    def pass_stats(self, pass_id):
        events = [e for e in self.events if e["pass"] == pass_id]
        return {
            "pass": pass_id,
            "observations": sum(e["visible"] for e in events),
            "new_landmarks": sum(e["created"] for e in events),
            "reused_landmarks": sum(e["reused"] for e in events),
            "relation_updates": sum(e["relation_updates"] for e in events),
            "final_landmarks": self.landmarks.__len__(),
            "final_relations": self.relations.__len__(),
        }


# ============================================================
# Trajectory
# ============================================================

def make_trajectory(steps=96):
    points = []
    for t in range(steps):
        a = 2 * math.pi * t / steps
        x = 4.0 + 4.4 * math.cos(a)
        y = 3.8 + 3.2 * math.sin(a)
        z = 2.0 + 0.8 * math.sin(2 * a)
        points.append(np.array([x, y, z]))
    return points


def direction_for_path(path, i):
    if i == 0:
        return path[1] - path[0]
    if i == len(path) - 1:
        return path[-1] - path[-2]
    return path[i + 1] - path[i - 1]


# ============================================================
# Experiment
# ============================================================

def run():
    print("=" * 80)
    print("E36 v4b — LOCAL RELATIONAL MEMORY / DOUBLE TRAVERSAL")
    print("=" * 80)

    world = make_world()
    path = make_trajectory()
    memory = RelationalMemory()

    rows = []
    total_raw_observations = 0
    ever_seen = set()
    pass_summaries = {}

    # Two identical traversals, retaining memory between them.
    for pass_id in (1, 2):
        memory.begin_pass()
        pass_raw = 0
        pass_unique = set()
        previous_position = None
        previous_direction = None

        for t, position in enumerate(path):
            direction = direction_for_path(path, t)
            observer = Observer(position=position, direction=direction)
            visible = observe(observer, world)

            # Evaluator-only coverage accounting.
            for item in visible:
                pass_unique.add(item["world_index"])
                ever_seen.add(item["world_index"])

            local = memory_observations(visible)

            if previous_position is None:
                motion_delta = np.zeros(3)
            else:
                motion_delta = position - previous_position

            rot_delta = rotation_delta(previous_direction, direction)

            # Hard boundary assertion: these keys are the only things
            # memory is allowed to receive.
            allowed_keys = {"relative_position", "feature", "distance"}
            assert all(set(obs.keys()) == allowed_keys for obs in local)
            assert not any("world_index" in obs for obs in local)

            memory.update(
                local,
                timestep=t,
                pass_id=pass_id,
                motion_delta=motion_delta,
                rotation_delta=rot_delta,
            )

            pass_raw += len(local)
            total_raw_observations += len(local)
            previous_position = position.copy()
            previous_direction = direction.copy()

            rows.append({
                "pass": pass_id,
                "timestep": t,
                "visible": len(local),
                "unique_seen_this_pass": len(pass_unique),
                "unique_seen_total": len(ever_seen),
                "landmarks": len(memory.landmarks),
                "relations": len(memory.relations),
                "knowledge_cost_slots": memory.cost_slots(),
                "raw_observation_cost_slots": memory.raw_cost(total_raw_observations),
                "compression_ratio": (
                    memory.cost_slots() / memory.raw_cost(total_raw_observations)

                ),
                "created": memory.events[-1]["created"],
                "reused": memory.events[-1]["reused"],
                "expanded": memory.events[-1]["expanded"],
            })

            if t % 24 == 0 or t == len(path) - 1:
                event = memory.events[-1]
                print(
                    f"pass={pass_id} t={t:3d} | "
                    f"visible={len(local):3d} | "
                    f"new={event['created']:2d} | "
                    f"reuse={event['reused']:2d} | "
                    f"landmarks={len(memory.landmarks):3d} | "
                    f"relations={len(memory.relations):4d} | "
                    f"cost={memory.cost_slots():5d}"
                )

        pass_summaries[pass_id] = {
            "observations": pass_raw,
            "unique_world_points_seen_evaluator_only": len(pass_unique),
            "new_landmarks_created": sum(
                e["created"] for e in memory.events if e["pass"] == pass_id
            ),
            "landmarks_reused_from_prior_memory": sum(
                e["reused"] for e in memory.events if e["pass"] == pass_id
            ),
            "final_landmarks_after_pass": len(memory.landmarks),
            "final_relations_after_pass": len(memory.relations),
        }

    p2 = pass_summaries[2]

    p1_new = p1["new_landmarks_created"]
    p2_new = p2["new_landmarks_created"]
    p2_reuse = p2["landmarks_reused_from_prior_memory"]

    # The second pass should not create another copy of the same learned
    # landmarks. This is the primary reuse signal.

        p2_reuse / (p2_reuse + p2_new)
        if (p2_reuse + p2_new) else 0.0
    )

        "experiment": "E36 v4b — local relational memory / double traversal",
        "world_points": len(world.voxels),
        "timesteps_per_pass": len(path),

        "pass_summaries": pass_summaries,
        "total_unique_world_points_seen_evaluator_only": len(ever_seen),
        "final_landmarks": len(memory.landmarks),
        "final_relations": len(memory.relations),
        "total_raw_observations": total_raw_observations,
        "final_knowledge_cost_slots": memory.cost_slots(),
        "raw_observation_cost_slots": memory.raw_cost(total_raw_observations),
        "knowledge_to_raw_ratio": (
            memory.cost_slots() / memory.raw_cost(total_raw_observations)
        ),
        "pass2_landmark_reuse_fraction": reuse_fraction,
        "pass2_new_landmarks_vs_pass1": (
            p2_new / p1_new if p1_new else None
        ),
        "absolute_world_coordinates_given_to_memory": False,
        "world_index_given_to_memory": False,
        "position_derived_features": False,
        "hidden_geometry_given_to_memory": False,
        "movement_used_as_temporal_transition": True,
        "relational_memory": True,
        "double_pass_reuse": True,
        "trajectory": rows,
        "memory_events": memory.events,
    }

    out = Path("synthetic_latent_e36_local_relational_v4b")
    out.mkdir(exist_ok=True)
    (out / "e36_summary.json").write_text(json.dumps(results, indent=2))

    # --------------------------------------------------------

    t1 = [r["timestep"] for r in rows if r["pass"] == 1]
    t2 = [r["timestep"] for r in rows if r["pass"] == 2]

#!/usr/bin/env python3
"""
E36 — Local Observer / Adaptive Information Memory

Concept:
    The observer moves through a 3-D world over time.

    At each timestep it receives ONLY information that is currently
    visible from its position/orientation. Hidden geometry is never
    passed to the memory system.

    Memory is allowed to grow dynamically:
        - update an existing chunk
        - create a new chunk
        - merge compatible chunks

    The experiment asks whether a useful information topology can
    emerge from traversal rather than being imposed by giving the
    observer the whole world.

This is deliberately a small conceptual prototype before integrating
the mechanism into the existing latent experiments.
"""

from __future__ import annotations

import json
import math
from dataclasses import dataclass, field
from pathlib import Path

import matplotlib.pyplot as plt
import numpy as np


# ============================================================
# World
# ============================================================

@dataclass
class Voxel:
    pos: np.ndarray
    feature: np.ndarray


@dataclass
class World:
    voxels: list[Voxel]


def make_world(seed: int = 36) -> World:
    rng = np.random.default_rng(seed)

    voxels = []

    # Three spatial structures with partially overlapping feature
    # statistics. They are deliberately not exposed as object IDs.
    structures = [
        (np.array([0.0, 0.0, 0.0]), 2.5, 90),
        (np.array([7.0, 1.5, 2.0]), 2.0, 70),
        (np.array([2.0, 7.0, 3.5]), 2.2, 80),
        (np.array([8.0, 7.0, 1.0]), 1.6, 60),
    ]

    for center, radius, count in structures:
        for _ in range(count):
            d = rng.normal(size=3)
            d /= np.linalg.norm(d)
            r = radius * (rng.random() ** (1.0 / 3.0))
            pos = center + d * r

            # Feature is local appearance, not an object label.
            feature = np.array([
                math.sin(pos[0] * 0.7),
                math.cos(pos[1] * 0.6),
                math.sin(pos[2] * 0.9),
                r / 3.0,
            ])

            feature += rng.normal(0, 0.035, size=4)
            voxels.append(Voxel(pos.astype(float), feature.astype(float)))

    return World(voxels)


# ============================================================
# Observer / visibility
# ============================================================

@dataclass
class Observer:
    position: np.ndarray
    direction: np.ndarray
    fov_degrees: float = 75.0
    max_range: float = 7.0


def normalize(v):
    n = np.linalg.norm(v)
    return v / n if n > 1e-12 else v


def line_of_sight(origin, target, world: World, ignore_index: int):
    """
    Approximate occlusion with spherical blockers around world points.

    The observer receives no information about a target if another
    world point lies sufficiently close to the ray before it.
    """
    ray = target - origin
    distance = np.linalg.norm(ray)
    if distance < 1e-9:
        return True

    ray = ray / distance

    for i, voxel in enumerate(world.voxels):
        if i == ignore_index:
            continue

        rel = voxel.pos - origin
        along = np.dot(rel, ray)

        if along <= 0.0 or along >= distance:
            continue

        closest = origin + ray * along
        lateral = np.linalg.norm(voxel.pos - closest)

        # Larger points block more strongly at close range.
        blocker_radius = 0.20 + 0.015 * along

        if lateral < blocker_radius:
            return False

    return True


def observe(observer: Observer, world: World):
    visible = []

    forward = normalize(observer.direction)
    cos_half_fov = math.cos(math.radians(observer.fov_degrees / 2))

    for i, voxel in enumerate(world.voxels):
        rel = voxel.pos - observer.position
        distance = np.linalg.norm(rel)

        if distance < 1e-9 or distance > observer.max_range:
            continue

        direction = rel / distance
        if np.dot(direction, forward) < cos_half_fov:
            continue

        if line_of_sight(observer.position, voxel.pos, world, i):
            visible.append({
                "world_index": i,
                "relative_position": rel.copy(),
                "feature": voxel.feature.copy(),
                "distance": float(distance),
            })

    return visible


# ============================================================
# Adaptive memory
# ============================================================

@dataclass
class Chunk:
    centroid: np.ndarray
    feature_centroid: np.ndarray
    observations: list[dict] = field(default_factory=list)
    last_seen: int = -1


class AdaptiveMemory:
    """
    No fixed spatial buckets.

    A new observation is compared with existing memory using only
    information the observer has already acquired.

    If it is sufficiently compatible with a remembered region,
    that chunk expands. Otherwise a new chunk is created.

    Periodically, compatible chunks may merge.

    The thresholds are deliberately simple and exposed so the next
    experiment can replace them with a learned decision mechanism.
    """

    def __init__(
        self,
        position_gate=1.35,
        feature_gate=0.65,
        merge_gate=1.10,
    ):
        self.chunks: list[Chunk] = []
        self.position_gate = position_gate
        self.feature_gate = feature_gate
        self.merge_gate = merge_gate

        self.events = []

    def _score(self, obs, chunk):
        p = np.linalg.norm(
            obs["relative_position"] - chunk.centroid
        )
        f = np.linalg.norm(
            obs["feature"] - chunk.feature_centroid
        )
        return p, f

    def update(self, observations, timestep, observer_position):
        created = 0
        updated = 0

        for obs in observations:
            # Convert relative observation into the observer's accumulated
            # world-relative coordinate frame. The observer is allowed to
            # know where it currently is and where it has been.
            absolute_estimate = (
                observer_position + obs["relative_position"]
            )

            candidate = None
            best_score = float("inf")

            for chunk in self.chunks:
                p = np.linalg.norm(
                    absolute_estimate - chunk.centroid
                )
                f = np.linalg.norm(
                    obs["feature"] - chunk.feature_centroid
                )

                if p <= self.position_gate and f <= self.feature_gate:
                    score = p + f
                    if score < best_score:
                        best_score = score
                        candidate = chunk

            record = {
                "position": absolute_estimate.copy(),
                "feature": obs["feature"].copy(),
                "timestep": timestep,
            }

            if candidate is None:
                self.chunks.append(
                    Chunk(
                        centroid=absolute_estimate.copy(),
                        feature_centroid=obs["feature"].copy(),
                        observations=[record],
                        last_seen=timestep,
                    )
                )
                created += 1
            else:
                n = len(candidate.observations)
                candidate.centroid = (
                    candidate.centroid * n + absolute_estimate
                ) / (n + 1)

                candidate.feature_centroid = (
                    candidate.feature_centroid * n
                    + obs["feature"]
                ) / (n + 1)

                candidate.observations.append(record)
                candidate.last_seen = timestep
                updated += 1

        merged = self.merge_compatible(timestep)

        self.events.append({
            "timestep": timestep,
            "visible": len(observations),
            "chunks": len(self.chunks),
            "created": created,
            "updated": updated,
            "merged": merged,
        })

    def merge_compatible(self, timestep):
        merged = 0
        changed = True

        while changed:
            changed = False

            for i in range(len(self.chunks)):
                if changed:
                    break

                for j in range(i + 1, len(self.chunks)):
                    a = self.chunks[i]
                    b = self.chunks[j]

                    p = np.linalg.norm(a.centroid - b.centroid)
                    f = np.linalg.norm(
                        a.feature_centroid - b.feature_centroid
                    )

                    if p <= self.merge_gate and f <= self.feature_gate:
                        all_obs = a.observations + b.observations
                        n = len(all_obs)

                        positions = np.asarray(
                            [x["position"] for x in all_obs]
                        )
                        features = np.asarray(
                            [x["feature"] for x in all_obs]
                        )

                        a.centroid = positions.mean(axis=0)
                        a.feature_centroid = features.mean(axis=0)
                        a.observations = all_obs
                        a.last_seen = max(
                            a.last_seen,
                            b.last_seen,
                        )

                        del self.chunks[j]
                        merged += 1
                        changed = True
                        break

        return merged

    def memory_size(self):
        # Structural cost + stored observations.
        return sum(
            8 + 4 * len(c.observations)
            for c in self.chunks
        )


# ============================================================
# Trajectory
# ============================================================

def make_trajectory(steps=96):
    points = []

    for t in range(steps):
        a = 2 * math.pi * t / steps

        # A looping path that passes through regions from different
        # directions, then revisits the starting area.
        x = 4.0 + 4.4 * math.cos(a)
        y = 3.8 + 3.2 * math.sin(a)
        z = 2.0 + 0.8 * math.sin(2 * a)

        points.append(np.array([x, y, z]))

    return points


def direction_for_path(path, i):
    if i == 0:
        return path[1] - path[0]
    if i == len(path) - 1:
        return path[-1] - path[-2]
    return path[i + 1] - path[i - 1]
